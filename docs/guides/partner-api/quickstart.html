Quick start: zero to first delivered notification

Twenty minutes from nothing to a notification with status SENT, using the DEV deployment and a synthetic test user. Each step has the exact command and the real answer.

Overview

  1. Make a key pair and send the public half and your server's address to Adera.
  2. Receive a key id, the base URL, template ids.
  3. Check connectivity with a signed GET /v1/templates.
  4. Send a notification to the synthetic user u_p_test_ok.
  5. Read the status until it is SENT.
  6. Receive the callback.
  7. Next steps.
What you need to know first

You send notifications to Adera users through your server only (never from a browser or a mobile app: the private key must stay secret). You address users by pseudonymous ids and send only approved templates. Read the overview for the concepts; this page is the shortest path.

1. Make a key pair, tell Adera

openssl genrsa -out partner.pem 2048
openssl rsa -in partner.pem -pubout -out partner.pub

Send Adera staff: (a) the contents of partner.pub (-----BEGIN PUBLIC KEY-----), never the private key; (b) the public IP address (or range) your server's outgoing requests come from, for DEV; (c) which channels you need (SMS, EMAIL, in-app) and your expected volume; (d) the messages you want to send, in the languages you need (they become templates: partners cannot create them). Adera staff do what is listed in the staff checklist.

Copy the examples/ folder of this guide next to your key. It has the signing helpers in Python (needs pip install cryptography requests), Node.js (18+, no dependencies) and shell (curl and openssl). Pick one; the steps below show the shell version and the Python/Node equivalents.

3. Check connectivity: GET /v1/templates

./examples/adera_call.sh GET /v1/templates

Expected: HTTP/1.1 200 and a JSON array of your templates (here truncated):

HTTP/1.1 200
Content-Type: application/json
X-Adera-Key-Id: adera-sig-202610
X-Adera-Timestamp: 1793012301
X-Adera-Signature: ...

[{"id":"7d51f90e-...","code":"future-offer", ... },{"id":"ef3c8771-df6c-477c-b5a8-7ba94c2fded3","code":"job-accepted","kind":"DIRECT","params":[{"name":"name","required":true,"maxLength":30,"allowLinks":false}, ...], ...}]

Python: from adera_client import call; print(call("GET", "/v1/templates").json()). Node: require("./adera-client").call("GET", "/v1/templates").then(console.log).

If you getIt means
403 ip_not_allowedAdera does not know your server's address yet. Tell staff the address your requests really leave from.
401 invalid_signatureYour canonical string differs from Adera's: use the test vector and the checklist.
401 stale_timestampYour clock is off by more than 5 minutes.
401 unknown_keyTypo in the key id, or the key was registered on another deployment.
403 wrong_environmentYou used a ak_prod_... key against DEV (or the reverse).
403 app_killedStaff stopped the app. (A DRAFT app works on DEV.)

Changes staff make (address list, capabilities, status, key revocation) take up to 15 seconds to apply.

4. Send the first notification

Use the synthetic test user u_p_test_ok: it exists in DEV for every app, needs no issuing, and nothing is sent to anybody.

printf '%s' '{"externalId":"qs-1","userId":"u_p_test_ok","templateId":"'$TEMPLATE_ID'","params":{"name":"Abebe"}}' > body.json
./examples/adera_call.sh POST /v1/notifications body.json
HTTP/1.1 202
Content-Type: application/json
X-Adera-Key-Id: adera-sig-202610
...

{"notificationId":"c1ae35d4-5d15-4115-acfa-473d2fba996e","externalId":"qs-1","status":"QUEUED","channel":"SMS","environment":"DEV","createdAt":"2026-10-26T11:18:27.560943Z","expiresAt":"2026-10-27T11:18:27.560774Z"}

Python: python examples/send.py qs-1 u_p_test_ok $TEMPLATE_ID. Node: node examples/send.js qs-1 u_p_test_ok $TEMPLATE_ID (both use {"name":"Abebe"}; adapt params to your template).

202 and QUEUED mean "accepted". channel: "SMS" was chosen by Adera because the template is DIRECT and your app may send SMS. Sending the identical request again returns 200 with "replayed": true and sends nothing twice.

5. Read the status

./examples/adera_call.sh GET /v1/notifications/qs-1
{"notificationId":"c1ae35d4-5d15-4115-acfa-473d2fba996e","externalId":"qs-1","status":"SENT","channel":"SMS","environment":"DEV","createdAt":"2026-10-26T11:18:27.560943Z","expiresAt":"2026-10-27T11:18:27.560774Z","completedAt":"2026-10-26T11:18:28.486769Z","attempts":1}

SENT about a second later: the first notification is delivered (simulated, because u_p_test_ok is synthetic). For a real DEV test user (an id Adera staff issue for your app) the SMS text appears in the dev SMS log and the email in the dev mail catcher.

6. Receive the callback

Run the callback receiver (Python: python examples/callback_receiver.py 8099; Node: node examples/callback-receiver.js 8099), then send again with a callbackUrl that Adera's DEV can reach (on Adera's own dev stack: the address of your machine as seen from the dev containers, for example the Docker bridge http://172.18.0.1:8099/adera/hook; production needs public https):

printf '%s' '{"externalId":"qs-2","userId":"u_p_test_ok","templateId":"'$TEMPLATE_ID'","params":{"name":"Abebe"},"callbackUrl":"http://172.18.0.1:8099/adera/hook"}' > body.json
./examples/adera_call.sh POST /v1/notifications body.json

The receiver prints, a moment after the 202:

callback notification.status {"at": "2026-10-26T11:19:02.1...Z", "event": "notification.status", "reason": null, "status": "SENT", "channel": "SMS", "externalId": "qs-2", "environment": "DEV", "notificationId": "..."}

The receiver already verified Adera's signature and ignores duplicates (details).
