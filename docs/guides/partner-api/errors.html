Error codes

The complete table of what the partner API can answer when something is wrong: status, error code, cause and fix. Every example was reproduced on the dev stack unless marked otherwise.

Overview

  • Errors are JSON {"error": "<code>", ...details} with the HTTP status. Branch on the status and the error code. Details: fields (object {"name": "reason"}), limit and channel, capability.
  • Errors produced by Adera's API (every {"error": code} answer in the tables below, 400, 401, 403, 404 template_not_found / not_found, 409, 413, 422, 429 quota_exceeded, 503) are signed like successes (same three X-Adera-* headers), so you can verify them. Answers generated by the gateway or by the web framework (last table: unknown path, wrong method, wrong media type) are not signed.
  • Rule of thumb: 4xx means your request must change before retrying (except 429, which means wait), 5xx means retry the same request later with backoff.
  • A refused request stores nothing and uses no quota.

Authentication, environment and address (every endpoint)

Checked in this order (the first failure wins), before the endpoint looks at your request.

StatuserrorCauseFix
413request_too_largeBody larger than 64 KiB (checked first).Send a smaller body.
401missing_signatureOne of X-Adera-Key-Id, X-Adera-Timestamp, X-Adera-Signature is absent or blank.Send all three headers on every request.
401invalid_timestampX-Adera-Timestamp is not an integer (for example yesterday, or milliseconds with a decimal point).Unix seconds, digits only.
401stale_timestampThe timestamp differs from Adera's clock by more than 5 minutes, in either direction (verified for 1 hour old and 1 hour ahead).Sync your clock (NTP); generate the timestamp when you sign, not when you queue the job.
401unknown_keyNo key with that id on this deployment (typo, or a key id from another deployment's database).Use the id exactly as staff gave you; ask staff to check it is registered on this deployment.
401key_revoked_or_expiredThe key was revoked or its expiry date has passed (takes effect within about 15 s).Use another active key; ask staff to register a new one.
401invalid_signatureThe signature does not verify: wrong private key for this key id, or the method, path, query, timestamp or body bytes differ from what you signed, or the signature is not valid base64.Troubleshooting checklist.
403wrong_environmentThe signature is valid but the key belongs to the other environment than this deployment (ak_prod_... on DEV, or the reverse).Use the key id and base URL of the same environment.
401unknown_appThe key's mini app no longer exists. From the code, not reproduced.Contact Adera.
403app_draftPROD deployment and the app is still DRAFT.Ask staff to take the app live (or test on DEV, where DRAFT works).
403app_pausedPROD deployment and the app is PAUSED by staff.Contact Adera: the pause is deliberate.
403app_killedThe app was stopped by staff (any deployment).Contact Adera. Only a super admin can revive a killed app.
403app_not_activeFallback when the registry gives no specific reason. Should not occur.Contact Adera.
403ip_not_allowedThe address your request comes from is not in the app's allowed list for this environment, or the list is empty.Give staff your egress IP(s) for this environment (allowed addresses).
503service_unavailableAn Adera dependency (the registry or the user directory) is down or misconfigured. Also returned if the registry and the notification service disagree about their environment.Retry the same request later with backoff.

Real examples: 401 {"error":"missing_signature"}, 401 {"error":"invalid_timestamp"}, 401 {"error":"stale_timestamp"}, 401 {"error":"unknown_key"}, 401 {"error":"invalid_signature"} (body changed after signing; a signature of another request; a signature that is not base64), 403 {"error":"wrong_environment"}, 403 {"error":"ip_not_allowed"}, 401 {"error":"key_revoked_or_expired"} (revoked key; expired key), 413 {"error":"request_too_large"} (70 KB body).

Request errors (POST /v1/notifications and lookups)

StatuserrorCauseFix
400validation_failed + fieldsOne or more fields are missing, unknown or malformed. All problems are listed together.Fix every field in fields; do not retry unchanged. Examples below.
400invalid_requestThe body is not valid JSON, is empty, is null, is a JSON array rather than an object, or a path parameter has the wrong type (a non-UUID template id).Send a JSON object with Content-Type: application/json.

409external_id_reusedThis externalId was used before for a different request (any difference in templateId, userId, params, data, callbackUrl, ttlSeconds).A new message needs a new externalId. To repeat the old one, send exactly the old request.

422template_inactiveStaff switched the template off (active: false).Use another template or ask staff.

422template_expiredNow is at or after the template's expiresAt.Ask staff for a new template or to extend it.
422user_unreachableAdera cannot reach this person: unknown or never-issued id (or one of another app), deleted, suspended, no phone and no email for a DIRECT template, or u_p_test_unreachable. Deliberately generic.Stop sending to this id; do not retry. See unreachable users.
422synthetic_user_not_allowedA u_p_test_* id was used on a PROD deployment. From the code, not reproducible on the dev stack.Test ids exist only in DEV.
403capability_not_granted + capabilityThe channel Adera chose (by template kind and the user's contact data) needs notify.sms, notify.email or notify.inapp, which the app does not have in state GRANTED.Ask staff to grant the capability named in the answer.
429quota_exceeded + limit + channelA per-app quota is used up: max_total, max_per_user_per_day, max_per_day or max_distinct_users_per_day (channel is SMS, EMAIL or IN_APP).See what to do per limit.
200status SUPPRESSED (not an error)The user muted this channel for your app.Final; see muted users.

Answers that are not in the {"error": code} shape

These come from the web framework, not from Adera's API code. They have the framework's body and, verified, no signature headers (404, 405 and 415 were checked). Do not treat a missing signature on these as an attack; do treat a missing signature on an {"error": code} answer as suspicious:

StatusBodyCauseFix
404{"timestamp":"...","status":404,"error":"Not Found","path":"/v1/nothing"}The path does not exist (also a trailing slash: /v1/notifications/doc-first/).Use the documented paths.
405{"timestamp":"...","status":405,"error":"Method Not Allowed","path":"/v1/notifications"}Wrong method: DELETE or POST on /v1/notifications/{externalId}, GET on /v1/notifications (there is no list endpoint), PUT on templates.Use GET for templates and status, POST to send.
415{"timestamp":"...","status":415,"error":"Unsupported Media Type","path":"/v1/notifications"}A POST without Content-Type: application/json.Send the header.
429the gateway's own body (not signed)More than 600 requests per 60 s from your IP (120 on the JWKS route).Slow down; see the X-RateLimit-* headers.
502, 503, 504gateway body (not signed)The gateway cannot reach the service.Retry later with backoff, same externalId.
500framework body (probably not signed)An unexpected failure inside Adera. Not reproduced.Retry later with the same externalId; if it persists, give Adera the X-Request-Id header and your externalId.

Retry guide

AnswerRetry?
202, 200 (any)No: success (a replay 200 is also success).
network error / timeout / no answerYes, the same request with the same externalId, with backoff.
5xx, gateway 429Yes, with backoff.
401 stale_timestampYes after fixing the clock; sign anew (a new timestamp) on every attempt.
429 quota_exceededDaily limits: after 00:00 UTC. max_total: not until staff raise it.
403 capability_not_granted, app_*, ip_not_allowedOnly after Adera staff change the configuration (allow about 15 s).
400, 404, 409, 422 (except what is noted above)No: change the request.

Staff-side endpoints (/admin/api/v1) have their own codes (for example 403 insufficient_role or 409 template_code_taken); they are not part of the partner API.
