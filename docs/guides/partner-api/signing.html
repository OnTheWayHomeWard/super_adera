Signing requests: ADERA-SIG-1

How every call to the partner API is authenticated, how you check that an answer or a callback really came from Adera, and complete runnable code in Python, Node.js and curl with openssl.

Overview

ADERA-SIG-1 is a request-signing scheme based on RS256 (RSASSA-PKCS1-v1_5 with SHA-256). You generate an RSA key pair, keep the private key on your server, and give Adera staff only the public key. Each request carries a signature that proves (1) you hold the private key, (2) nobody changed the method, path, query or body, and (3) the request is fresh. The same idea works in the other direction: Adera signs every answer and every callback with its own key, and you verify with the public key published at /.well-known/jwks.json.

Why not an API token

With a shared secret or a bearer token, anyone who steals the token (a log file, a proxy, a leaked config) can impersonate the partner, and Adera has to store something that can impersonate the partner. With a signature scheme Adera holds only a public key, so a breach on Adera's side cannot be used to send requests as you, and a stolen signed request cannot be altered or reused for another call.

Request headers

HeaderValueNotes
X-Adera-Key-IdThe key id staff gave you, e.g. ak_dev_b05f96cc4740e2a118a55282Identifies your app and the environment of the key (ak_dev_... or ak_prod_...).
X-Adera-TimestampCurrent unix time in whole seconds, e.g. 1793000000Must be within 5 minutes of Adera's clock, in either direction. Keep your server clock in sync (NTP).
X-Adera-SignatureBase64 of the RS256 signature of the canonical stringStandard base64 (with padding) is what you should send; URL-safe base64, with or without padding, is also accepted.
Content-Typeapplication/json on requests with a bodyNot part of the signature.

The canonical string

The signature is computed over exactly five lines joined by a single line feed (\n, byte 0x0A), with no trailing newline:

ADERA-SIG-1
{timestamp}
{METHOD}
{path[?query]}
{base64(sha256(body))}
LineExact rule
1The literal text ADERA-SIG-1. It names the scheme and its version.
2The same digits you put in X-Adera-Timestamp.
3The HTTP method in upper case: GET or POST.
4The request target as it goes on the wire: the path starting with /, then ? and the raw query string if there is one. No scheme, no host, no fragment. Not decoded and not re-encoded: if your HTTP library rewrites the path or query (percent-encoding, reordering), you must sign what it actually sends. The path of GET /v1/notifications/doc-first is /v1/notifications/doc-first. A trailing slash is a different path (and a 404).
5Standard base64 (with padding) of the SHA-256 digest of the raw request body bytes. For a request without a body (every GET) it is the hash of zero bytes: 47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU=.

The signature is then base64( RSASSA-PKCS1-v1_5-SHA256( privateKey, UTF-8 bytes of the canonical string ) ). Keys must be RSA, at least 2048 bits.

A test vector you can check your code against

Take this exact body (one line, 148 bytes, no trailing newline), timestamp 1793000000, method POST, path /v1/notifications:

{"externalId":"job-1","userId":"u_p_0123456789abcdef0123456789abcdef","templateId":"ef3c8771-df6c-477c-b5a8-7ba94c2fded3","params":{"name":"Abebe"}}

The body hash must be 7sxkQQvLi9R1R8MaP5HHBwUYp8pVDWFjFc3pfp4bQ+Y= and the canonical string must be (shown with \n for the line breaks):

ADERA-SIG-1\n1793000000\nPOST\n/v1/notifications\n7sxkQQvLi9R1R8MaP5HHBwUYp8pVDWFjFc3pfp4bQ+Y=

RS256 with PKCS#1 v1.5 padding is deterministic: the same key and the same canonical string always give the same signature, so you can compare your signature byte for byte with another implementation (for example with openssl, below) using your own test key.

Rules that cause most mistakes

  • Serialize the JSON once. Hash and send the same byte string. Do not hash JSON.stringify(x) and let the HTTP library serialize x again: key order or spacing may differ and the hash will not match (401 invalid_signature). The examples below turn the body into bytes first and pass those bytes to both the hash and the request.
  • The body can be in any JSON formatting (spaces, key order). Adera hashes the bytes you sent. The idempotency check on externalId compares the meaning of the request, not its bytes (see idempotency).
  • Query strings are signed. /v1/templates?x=1 and /v1/templates need different signatures. Adding a query after signing gives invalid_signature.
  • Timestamps older or newer than 5 minutes are refused with 401 stale_timestamp. A non-numeric value gives 401 invalid_timestamp.
  • No nonce. A captured signed request can be sent again during its 5-minute window and will be accepted. For POST /v1/notifications that is harmless (the same externalId is a replay and sends nothing twice) and for GET requests it is read-only; sign requests only over HTTPS anyway.
  • Maximum body: 64 KiB, otherwise 413 request_too_large (checked before the signature).

Make a key pair

On your own machine (not on Adera's side, not in a shared tool). Keep partner.pem secret; send staff only partner.pub.

openssl genrsa -out partner.pem 2048
openssl rsa -in partner.pem -pubout -out partner.pub
cat partner.pub        # -----BEGIN PUBLIC KEY----- ...   this is what you send to Adera staff

Staff register the public key and give you back a key id. Adera refuses anything containing PRIVATE KEY (validation_failed on their side: the dashboard says "that is a PRIVATE key. Never send it"). Generating a key pair in the Adera dashboard and handing you the private half is possible only as a convenience in DEV; for PROD always generate your own. See key lifecycle.

The examples below read three environment variables (the values here are the throwaway ones used to capture the outputs on this page):

export ADERA_BASE=http://127.0.0.1:9080               # the base URL of the deployment (dev stack)
export ADERA_KEY_ID=ak_dev_b05f96cc4740e2a118a55282    # given to you by Adera staff
export ADERA_PRIVATE_KEY_FILE=$PWD/partner.pem        # your PRIVATE key file

All the files below are also in the examples/ folder next to these pages.

Python (cryptography and requests)

Install: pip install cryptography requests. This client signs requests, verifies the signature of every answer (raising an exception if it is wrong) and contains verify_callback for your callback endpoint. File examples/adera_client.py:

"""Minimal Adera partner API client. Needs: pip install cryptography requests
Environment: ADERA_BASE (e.g. https://api.example), ADERA_KEY_ID, ADERA_PRIVATE_KEY_FILE (PEM, your PRIVATE key)."""
import base64, hashlib, json, os, time
import requests
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.hazmat.primitives.asymmetric import padding, rsa

BASE = os.environ["ADERA_BASE"].rstrip("/")
KEY_ID = os.environ["ADERA_KEY_ID"]
with open(os.environ["ADERA_PRIVATE_KEY_FILE"], "rb") as f:
    PRIVATE_KEY = serialization.load_pem_private_key(f.read(), password=None)


def b64(data: bytes) -> str:
    return base64.b64encode(data).decode()


def sha256_b64(data: bytes) -> str:
    return b64(hashlib.sha256(data).digest())


def rs256_sign(canonical: str) -> str:
    return b64(PRIVATE_KEY.sign(canonical.encode(), padding.PKCS1v15(), hashes.SHA256()))


def call(method: str, path: str, body: dict | None = None):
    """Send one signed request. `path` includes the query string exactly as it goes on the wire."""
    raw = json.dumps(body, separators=(",", ":")).encode() if body is not None else b""
    ts = str(int(time.time()))
    canonical = "\n".join(["ADERA-SIG-1", ts, method.upper(), path, sha256_b64(raw)])
    signature = rs256_sign(canonical)
    response = requests.request(
        method, BASE + path, data=raw if raw else None, timeout=15,
        headers={"X-Adera-Key-Id": KEY_ID, "X-Adera-Timestamp": ts, "X-Adera-Signature": signature,
                 "Content-Type": "application/json"})
    verify_response(response, signature)
    return response


# ---- verifying what Adera sends back (responses AND callbacks) ---------------------------------------------------

_jwks_cache: dict = {}


def adera_public_key(kid: str):
    """Adera's public key from /.well-known/jwks.json, cached for an hour (refetch once if the kid is unknown)."""
    entry = _jwks_cache.get(kid)
    if entry is None or time.time() - entry[1] > 3600:
        keys = requests.get(BASE + "/.well-known/jwks.json", timeout=10).json()["keys"]
        for k in keys:
            n = int.from_bytes(base64.urlsafe_b64decode(k["n"] + "=" * (-len(k["n"]) % 4)), "big")
            e = int.from_bytes(base64.urlsafe_b64decode(k["e"] + "=" * (-len(k["e"]) % 4)), "big")
            _jwks_cache[k["kid"]] = (rsa.RSAPublicNumbers(e, n).public_key(), time.time())
        entry = _jwks_cache.get(kid)
    if entry is None:
        raise ValueError("unknown Adera key id " + kid)
    return entry[0]


def _check(canonical: str, headers) -> None:
    ts = headers["X-Adera-Timestamp"]
    if abs(time.time() - int(ts)) > 300:
        raise ValueError("stale timestamp")
    key = adera_public_key(headers["X-Adera-Key-Id"])
    key.verify(base64.b64decode(headers["X-Adera-Signature"]), canonical.encode(), padding.PKCS1v15(), hashes.SHA256())  # raises if wrong


def verify_response(response: requests.Response, request_signature: str) -> None:
    if "X-Adera-Signature" not in response.headers:   # gateway answers (429, 502..504) and framework 404/405/415 are unsigned
        raise RuntimeError(f"unsigned answer, HTTP {response.status_code}: not produced by the API itself")
    ts = response.headers["X-Adera-Timestamp"]
    canonical = "\n".join(["ADERA-SIG-1-RESPONSE", ts, str(response.status_code), sha256_b64(response.content),
                           sha256_b64(request_signature.encode())])
    _check(canonical, response.headers)


def verify_callback(path_and_query: str, raw_body: bytes, headers) -> None:
    """Call this in your callback endpoint with the raw (unparsed) body and the request headers."""
    canonical = "\n".join(["ADERA-SIG-1", headers["X-Adera-Timestamp"], "POST", path_and_query, sha256_b64(raw_body)])
    _check(canonical, headers)

Node.js (18 or newer, no dependencies)

Uses only node:crypto and the built-in fetch. File examples/adera-client.js:

// Minimal Adera partner API client. Node 18+, no dependencies.
// Environment: ADERA_BASE, ADERA_KEY_ID, ADERA_PRIVATE_KEY_FILE (PEM, your PRIVATE key)
const crypto = require("node:crypto");
const fs = require("node:fs");

const BASE = process.env.ADERA_BASE.replace(/\/$/, "");
const KEY_ID = process.env.ADERA_KEY_ID;
const PRIVATE_KEY = crypto.createPrivateKey(fs.readFileSync(process.env.ADERA_PRIVATE_KEY_FILE));

const sha256b64 = (buf) => crypto.createHash("sha256").update(buf).digest("base64");
const rs256Sign = (canonical) => crypto.sign("sha256", Buffer.from(canonical), PRIVATE_KEY).toString("base64"); // RSASSA-PKCS1-v1_5

// path includes the query string exactly as it goes on the wire
async function call(method, path, body) {
  const raw = body === undefined ? Buffer.alloc(0) : Buffer.from(JSON.stringify(body));
  const ts = String(Math.floor(Date.now() / 1000));
  const canonical = ["ADERA-SIG-1", ts, method.toUpperCase(), path, sha256b64(raw)].join("\n");
  const signature = rs256Sign(canonical);
  const res = await fetch(BASE + path, {
    method, body: raw.length ? raw : undefined,
    headers: { "X-Adera-Key-Id": KEY_ID, "X-Adera-Timestamp": ts, "X-Adera-Signature": signature, "Content-Type": "application/json" },
  });
  const text = Buffer.from(await res.arrayBuffer());
  await verifyResponse(res, text, signature);
  return { status: res.status, body: text.length ? JSON.parse(text.toString()) : null };
}

// ---- verifying what Adera sends back (responses and callbacks) ----
const jwkCache = new Map(); // kid -> { key, at }
async function aderaPublicKey(kid) {
  let entry = jwkCache.get(kid);
  if (!entry || Date.now() - entry.at > 3600_000) {
    const { keys } = await (await fetch(BASE + "/.well-known/jwks.json")).json();
    for (const k of keys) jwkCache.set(k.kid, { key: crypto.createPublicKey({ key: k, format: "jwk" }), at: Date.now() });
    entry = jwkCache.get(kid);
  }
  if (!entry) throw new Error("unknown Adera key id " + kid);
  return entry.key;
}

async function check(canonical, h) { // h: function(name) -> header value
  if (Math.abs(Date.now() / 1000 - Number(h("x-adera-timestamp"))) > 300) throw new Error("stale timestamp");
  const key = await aderaPublicKey(h("x-adera-key-id"));
  if (!crypto.verify("sha256", Buffer.from(canonical), key, Buffer.from(h("x-adera-signature"), "base64"))) throw new Error("bad Adera signature");
}

async function verifyResponse(res, rawBody, requestSignature) {
  if (!res.headers.get("x-adera-signature")) // gateway answers (429, 502..504) and framework 404/405/415 are unsigned
    throw new Error(`unsigned answer, HTTP ${res.status}: not produced by the API itself`);
  const canonical = ["ADERA-SIG-1-RESPONSE", res.headers.get("x-adera-timestamp"), String(res.status), sha256b64(rawBody),
    sha256b64(Buffer.from(requestSignature))].join("\n");
  await check(canonical, (n) => res.headers.get(n));
}

// in your callback endpoint: rawBody is the unparsed body (Buffer), headers are Node's lower-cased request headers
async function verifyCallback(pathAndQuery, rawBody, headers) {
  const canonical = ["ADERA-SIG-1", headers["x-adera-timestamp"], "POST", pathAndQuery, sha256b64(rawBody)].join("\n");
  await check(canonical, (n) => headers[n]);
}

module.exports = { call, verifyCallback };

curl and openssl (no libraries)

Handy for a first try and for debugging. File examples/adera_call.sh (Linux and macOS; on macOS base64 works the same because the script strips line breaks itself):

#!/usr/bin/env bash
# Signed call to the Adera partner API with only curl and openssl.
# usage: adera_call.sh METHOD PATH [BODY_FILE]      e.g.  adera_call.sh POST /v1/notifications body.json
# env:   ADERA_BASE, ADERA_KEY_ID, ADERA_PRIVATE_KEY_FILE
set -euo pipefail
method=$(printf '%s' "$1" | tr a-z A-Z); path=$2; body_file=${3:-}

b64() { base64 | tr -d '\n'; }                       # one line, standard alphabet, with padding
ts=$(date +%s)
if [ -n "$body_file" ]; then body_hash=$(openssl dgst -sha256 -binary "$body_file" | b64)
else                          body_hash=$(openssl dgst -sha256 -binary </dev/null | b64); fi   # empty body = hash of zero bytes

# five lines joined by \n, no trailing newline; the body hash covers the exact bytes of BODY_FILE
canonical=$(printf 'ADERA-SIG-1\n%s\n%s\n%s\n%s' "$ts" "$method" "$path" "$body_hash")
signature=$(printf '%s' "$canonical" | openssl dgst -sha256 -sign "$ADERA_PRIVATE_KEY_FILE" | b64)   # RSASSA-PKCS1-v1_5 + SHA-256

args=(-sS -i -X "$method" "$ADERA_BASE$path"
      -H "X-Adera-Key-Id: $ADERA_KEY_ID" -H "X-Adera-Timestamp: $ts" -H "X-Adera-Signature: $signature"
      -H "Content-Type: application/json")
[ -n "$body_file" ] && args+=(--data-binary "@$body_file")      # --data-binary: curl must not alter a single byte
curl "${args[@]}"
printf '%s' '{"externalId":"doc-curl","userId":"'$ABEBE'","templateId":"'$JOB'","params":{"name":"Abebe"}}' > body.json
./adera_call.sh POST /v1/notifications body.json
./adera_call.sh GET  /v1/notifications/doc-curl

Debugging with curl

If you get invalid_signature, print what you sign: printf '%s' "$canonical" | cat -A shows $ at each line end and reveals stray carriage returns or a trailing newline. Hash the body file with openssl dgst -sha256 -binary body.json | base64 and compare with line 5. Use --data-binary, never -d/--data (curl would strip newlines).

Verifying Adera's answers

Every answer of the API under /v1/, errors included, carries three headers made with Adera's key (exceptions: see the note after the next code block):

HeaderValue
X-Adera-Key-IdAdera's key id (kid in the JWKS), e.g. adera-sig-202610
X-Adera-TimestampUnix seconds when Adera signed the answer
X-Adera-SignatureBase64 RS256 signature of the canonical response string below
ADERA-SIG-1-RESPONSE
{timestamp}
{HTTP status code}
{base64(sha256(response body bytes))}
{base64(sha256(the exact X-Adera-Signature string you sent in the request))}

The last line binds the answer to your request signature, so an answer cannot be replayed as the answer to a different request. The hash is over the signature header text (the base64 characters, as UTF-8 bytes), not over the decoded signature. The status code is the plain number (202). For an empty body the hash is the one of zero bytes. verify_response (Python) and verifyResponse (Node) above do exactly this; they also reject timestamps more than 5 minutes off.

Verification was exercised for every call in this section, including 400, 401, 403, 404 template_not_found, 413, 422 and 429 quota_exceeded answers. Not signed: answers produced by the gateway itself (rate limit 429, or 502/503/504 when a service is down) and the web framework's own bodies for an unknown path (404), a wrong method (405) and a missing content type (415), which only happen when your code calls something that does not exist. Treat a missing signature on a normal answer as "not from the API".

Decide your policy

An answer with a bad or missing signature must not be trusted: do not mark a notification as delivered, and do not retry blindly with a new externalId. Retry the same request (same externalId) later.

Adera's public key: /.well-known/jwks.json

GET /.well-known/jwks.json

Public, no signature needed, no login. It returns a standard JWK set with Adera's RSA public key. Cacheable: the answer carries Cache-Control: max-age=3600, public. Gateway limit 120 requests per minute per IP, so cache the key instead of fetching it per request (both clients above cache it for one hour and refetch once when they meet an unknown kid).

{"keys":[{"kty":"RSA","use":"sig","alg":"RS256","kid":"adera-sig-202610","n":"1hZGZIorMnraX4Ou21BKv-KaiT3an6XHPZPI9oXyGAbDE9_WZhGIPHpqkvO2LOZpXI6bhq... (base64url, 3072-bit modulus)","e":"AQAB"}]}
  • Pick the key whose kid equals the X-Adera-Key-Id of the answer or callback. Do not assume a single key or a fixed kid.
  • If Adera ever replaces its signing key, a new kid appears. When you meet a kid you do not know, refetch the JWKS (once, not in a loop) before rejecting. Adera has not published a rotation schedule; see known issues.
  • On a deployment that has no configured signing key, Adera generates a temporary one at start-up (kid starts with ephemeral-). That is only possible while no real SMS or email provider is enabled, so it never happens in production; in such a dev deployment the key changes on every restart, so your cache must handle a changed JWKS.
  • The same Adera key signs responses and callbacks. Always fetch the JWKS from the deployment you call (the dev and production deployments are separate and may use different keys).

Verifying callbacks

Callbacks use the request canonical string (Adera is the caller): ADERA-SIG-1\n{timestamp}\nPOST\n{path[?query] of your callbackUrl}\n{base64 sha256 of the raw body}, signed with Adera's key, with headers X-Adera-Key-Id, X-Adera-Timestamp, X-Adera-Signature, X-Adera-Event and Idempotency-Key. Ready-to-run receivers that verify the signature and de-duplicate are on Statuses and callbacks.

Troubleshooting invalid_signature

  1. Is the body you hash byte-identical to the body you send? Log both as bytes.
  2. Does the path include the query exactly as sent, and nothing else (no host)?
  3. Is the method upper case, and does the timestamp line equal the header?
  4. Is there a trailing newline in the canonical string? There must be none.
  5. Is the signature RSASSA-PKCS1-v1_5 with SHA-256 (not PSS, not SHA-1, not ECDSA)?
  6. Is the key id the one for this private key (a key id registered with a different public key fails here)?
  7. Is a proxy in front of your server rewriting the URL or re-encoding the body? Sign what leaves your machine.
