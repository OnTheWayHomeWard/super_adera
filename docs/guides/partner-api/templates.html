Templates

The approved messages your app may send. You read them here, fill in their declared values, and reference them by id when you send. You cannot create or change them.

Overview

A template is a message written in advance, in up to three languages, with named placeholders such as {name}. To notify a user you send the template's id and the values for its placeholders (params); Adera picks the user's language, fills the text in, and delivers it over the right channel.

Why partners cannot write free text

Messages arrive on users' phones as coming from Adera. Fixed, reviewed wording keeps Adera's SMS sender reputation and cost under control, stops a mini app from sending phishing links or spam through the official channel, and makes the three languages consistent. Values you fill in are plain text, limited in length, scanned for control characters and, unless the template allows it, for links. If you need a new message or a wording change, ask Adera staff to create or edit the template (staff action POST /admin/api/v1/notification/templates or PATCH .../{id}, role ADMIN).

Endpoints

GET/v1/templatesList my templates
Auth
Partner signature (X-Adera-Key-Id, X-Adera-Timestamp, X-Adera-Signature), allowed server address. See Signing.
Rate limit
600 per 60 s per client IP (gateway)
Parameters
none (a query string, if you add one, is ignored but must be signed)

Purpose

Discover which templates exist for your app, their ids, the values each needs, and exactly what each message says in each language. Call it at deployment time or on start-up, or cache it for a few minutes; template ids are stable. It returns all your templates, including inactive, not-yet-valid and expired ones, each with usableNow so you can tell.

./adera_call.sh GET /v1/templates

Errors

Only the common authentication and address errors (401 and 403 codes), 429 and 503.

GET/v1/templates/{id}One template
Auth
Partner signature, as above
Path parameter
id: the template's UUID

Purpose

Read a single template, for example to render a preview in your own admin screen, or to re-check usableNow before a bulk send.

Example request

./adera_call.sh GET /v1/templates/ef3c8771-df6c-477c-b5a8-7ba94c2fded3

Template fields

FieldTypeMeaning
idUUIDWhat you send as templateId.
appIdUUIDYour mini app. Always your own.
codestringA readable name chosen by staff, unique within your app (2 to 60 characters: lowercase letters, digits, _ . -), for example job-accepted. Use it for humans and logs; send the id, not the code.
kindDIRECT | IN_APPDecides the channel family, see below. Fixed at creation.
categoryTRANSACTIONAL | REMINDER | PROMOTIONALWhat kind of message it is. It is a label set by staff. Today it has no effect on delivery or limits; the intention is that PROMOTIONAL may be restricted more strictly later (quiet hours, opt-in). Keep promotional wording out of TRANSACTIONAL templates.
paramsarray (0 to 10)The values you must (or may) provide, see below.
contentobjectLanguage code (en, am, om) to texts. English is always present with a body.
activebooleanStaff can switch a template off. An inactive template cannot be sent (422 template_inactive).
validFrom, expiresAtISO-8601 instant or nullThe validity window. Before validFrom: 422 template_not_yet_valid. At or after expiresAt: 422 template_expired. Use it for campaigns and seasonal messages.
versionintegerStarts at 1; increases whenever staff change the text or the declared params.
usableNowbooleantrue when the template is active and now is inside its window. This is the same check the send endpoint applies.
unusableReasonstring or nullWhen usableNow is false: template_inactive, template_not_yet_valid or template_expired (the error you would get).
createdAt, updatedAtISO-8601Audit timestamps.

Kinds and which text is used

Text keyUsed byLimitNotes
titleIN_APP inbox and push title; email subject fallback100 charactersRequired in English for IN_APP templates.
bodyIN_APP inbox and push body; plain-text email body; SMS fallback1000Required in English for every template.
smsSMS text320If missing, body is sent as the SMS. Keep within 160 characters (70 if it contains non-Latin text such as Amharic) to stay within one SMS segment; longer texts are billed as several segments. Typographic punctuation (smart quotes, dashes, ellipsis, arrows, the euro sign) is replaced by plain equivalents when sent by SMS.
emailSubjectEmail subject150Falls back to title, then to the first 60 characters of body.
emailHtmlEmail HTML part20000Optional. Placeholder values are HTML-escaped when inserted here.
  • DIRECT (for example "your job was accepted", one-time information): delivered by SMS if the user has a phone number and your app has notify.sms, otherwise by email if the user has an email address and your app has notify.email. See channel selection.
  • IN_APP (for example "your ride is here"): written to the user's inbox inside the Adera app, plus a push notification to their devices. It needs notify.inapp. The inbox entry is the reliable part; push is best effort.

Params and placeholders

Each element of params declares one value:

FieldMeaning
nameThe placeholder name: starts with a letter, then letters, digits or _, up to 30 characters. In a text it is written {name}.
maxLengthMaximum characters of the value (1 to 500, default 100). Longer values are refused, they are not cut.
requiredtrue (default): the value must be present and non-empty. false: it may be left out; an unused optional placeholder is replaced by an empty string.
allowLinksfalse (default): the value may not look like a link. true: staff allowed links in this value (for example a tracking link in a promo).

What you send in params is checked like this (a failure is 422 param_invalid with fields naming every wrong value at once):

  • Every key you send must be a declared param ("not a parameter of this template").
  • Every required param must be present ("required").
  • Values must be text, numbers or booleans ("must be text or a number"); they are converted to text and trimmed.
  • No longer than maxLength ("longer than 30 characters") and no control characters such as line breaks ("contains control characters").
  • No links unless allowLinks is true ("links are not allowed in this value"). The exact rule (case-insensitive; since 2026-10-26 it no longer refuses ordinary names): a value is refused if it contains
    1. a scheme: http:, https: or any xyz://;
    2. www.;
    3. a host ending in a known domain ending (.com .net .org .et .app .io .co .me .ly .xyz .info .biz .link .click) followed by /, ?, # or :<digit>, such as evil.co/pay, evil.me?x=1 or evil.com:8080;
    4. a bare host with one of the unambiguous endings .com .net .org .et .app .info .biz .xyz .link .click, such as evil.com;
    5. a host with three or more parts that ends in any of the known endings, such as login.evil.co.
    Allowed: ordinary text, numbers and names, including a single word with an ambiguous ending and nothing after it: Hana.co, Sam.me, Al.io, Dr. Hana, 12.50 ETB. Because a bare name.co is allowed, the check stops phishing links but cannot be a complete URL detector: ask staff to keep allowLinks off for anything that is not meant to carry a link, and remember that templates are approved by staff and values are length-limited.

Real examples, all against the job-accepted template (name: required, 30 characters):

params {}                                  -> 422 {"error":"param_invalid","fields":{"name":"required"}}
params {"name":"A","color":"red"}          -> 422 {"error":"param_invalid","fields":{"color":"not a parameter of this template"}}
params {"name":"visit www.evil.example"}   -> 422 {"error":"param_invalid","fields":{"name":"links are not allowed in this value"}}
params {"name":"evil.co/pay"}              -> 422 (same body)    params {"name":"Hana.co"} -> accepted
IN_APP template, values make the title > 200 or body > 2000 chars after filling -> 422 {"error":"param_invalid","fields":{"title":"with these values the title would be longer than 200 characters (en)"}}
params {"name":"xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"} (31 x) -> 422 {"error":"param_invalid","fields":{"name":"longer than 30 characters"}}
params {"name":"a\nb"}                      -> 422 {"error":"param_invalid","fields":{"name":"contains control characters"}}
params {"name":{"a":1}}                     -> 422 {"error":"param_invalid","fields":{"name":"must be text or a number"}}
params {"name":"A","reference":"x"*21,"zzz":1} -> 422 {"error":"param_invalid","fields":{"zzz":"not a parameter of this template","reference":"longer than 20 characters"}}

A template with allowLinks: true accepts {"url": "https://example.com/spring"}; the real SMS text produced was Spring offer: https://example.com/spring.

Languages

Templates carry texts per language: en, am (Amharic), om (Afaan Oromo). The language is the user's language setting in the Adera app, read at delivery time; you do not send one. If the template has no text for the user's language, or lacks that particular key in it, the English text is used key by key. Verified with the three demo users: an English user got "Hi Abebe, your Adera job was accepted. Thank you!", an Amharic user got "ሰላም ሰላም፣ ሥራዎ ተቀባይነት አግኝቷል።", and an Afaan Oromo user got the English text because the template had no om content. Ask staff to add the languages your users need.

Validity, versions and timing

  • The validity window and active flag are checked when you send (acceptance). A notification already accepted is still delivered if the template is switched off or expires afterwards.
  • The template text is read at delivery time, so an edit by staff between acceptance and delivery applies to messages still in the queue (a deliberate decision, 2026-10-26: Adera keeps this behaviour and the staff edit form warns about it; for a different message staff create a new template). The version that was current at acceptance is stored for staff, but the delivered text is the current one.
  • Replaying a request (same externalId) returns the stored result even if the template has meanwhile become unusable.

What staff do Adera staff

  • POST /admin/api/v1/notification/templates creates a template for an app (appId, code, kind, category, params, content, optional active, validFrom, expiresAt); 409 template_code_taken when the code exists in that app. PATCH /admin/api/v1/notification/templates/{id} edits category, params, content, validity or the active flag (code and kind cannot change; changing params or content bumps version). Every placeholder used in a text must be a declared param. Role ADMIN. Template changes are not in the audit log (see known issues).
  • A change reaches the partner API immediately for template reads (templates are not cached on the partner side of the service).
