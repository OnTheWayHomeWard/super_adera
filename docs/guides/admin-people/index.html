Admin: users, staff, moderation and audit

How the owner and Adera's admins operate the platform through the admin API (and the backoffice screens that call it): sign-in and roles, the dashboard, registered users, moderation, staff, the audit log and notification visibility.

Audience

The owner, Adera's admins and developers who operate the platform. It documents every staff action that is not about configuring one mini app: staff sign-in and roles, the dashboard summary, registered users, moderation (reviews and reports), staff management, the audit log, cross-app notification visibility and the system page. Each entry is API first (path under /admin/api/v1) and names the equivalent screen of the backoffice (the staff dashboard at /backoffice/). Creating and configuring mini apps, keys, limits and templates is covered by a separate guide; this one only lists those endpoints where it needs to (permission matrix).

Authentication summary

  • Every call needs Authorization: Bearer $TOKEN where the token is a Kratos session token at aal2 (emailed code and authenticator-app code).
  • The caller must be an ACTIVE staff member; the role (VIEWER, ADMIN, SUPER_ADMIN) decides what is allowed.
  • Answers: 401 unauthorized, 403 mfa_required, 403 not_staff, 403 insufficient_role. Details on the page Staff sign-in, roles and permissions.
  • Limits at the gateway: 300 admin calls per minute and 10 sign-in submits per minute, both per IP.

Conventions

  • Errors: {"error": "code"}, with "fields": {"name": "message"} for validation_failed. See Error codes.
  • Ids are UUIDs (staff, users, apps, reviews, reports, notifications, audit events) except partner key ids (ak_dev_...). The staff id equals the person's Kratos identity id.
  • Timestamps are ISO-8601 in UTC (2026-10-26T10:56:44.614665Z); filters take instants like 2026-10-01T00:00:00Z.
  • Pagination differs by endpoint: users use page/size and answer {items, page, size, total}; reviews and reports use page/size and a plain array with the total in header X-Total-Count; the audit log and notification log use limit/offset (max 200) and X-Total-Count. Out-of-range sizes are clamped, not rejected.
  • Languages: the API itself answers in codes, not sentences. Per-language objects (en, am, om) appear in app names (for example draftApps[].name) and user language values.
  • Writes are JSON with Content-Type: application/json; several endpoints reject unknown fields so a typo never silently does nothing.
  • Audit: every successful change is audited under an action name (catalogue on the Audit log page).

Glossary

TermMeaning
Super appThe Adera app that customers use.
Mini appA partner service listed in the super app. Only staff create and configure them.
PartnerThe company behind a mini app; its backend sends notifications through the partner API.
Staff / adminA person who signs in to the backoffice or the admin API.
RoleVIEWER, ADMIN or SUPER_ADMIN.
aal1 / aal2Kratos authenticator assurance level: aal1 = emailed code only, aal2 = emailed code plus authenticator-app code. The admin API needs aal2.
BackofficeThe staff dashboard web app at /backoffice/.
ModerationHiding abusive reviews and working user reports.
Audit eventOne row of the audit log: who, what, on what, when, from where.
MaskingPartial hiding of contact data for VIEWER (+251*****0015).
Bootstrap super adminThe first SUPER_ADMIN, created at start-up from BOOTSTRAP_SUPER_ADMIN_EMAIL when none exists.
KratosOry Kratos, the identity system that holds customer and staff accounts and sessions.
CapabilityA permission a mini app may be granted (for example notify.sms).

VIEWER_TOKEN / ADMIN_TOKEN / SUPER_TOKEN=<tokens of staff with that role>
USER_ID, APP_ID, REVIEW_ID, REPORT_ID, STAFF_ID=<uuids from earlier answers>

All responses in this guide were captured on 2026-10-26 from the running dev stack (ADERA_ENV=dev) with temporary staff accounts and the seeded demo data; throwaway users, apps, reviews and colleagues created for the examples were removed afterwards. Counts such as X-Total-Count reflect that shared stack and will differ on yours.
