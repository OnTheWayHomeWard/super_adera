Error codes

Every error an admin API client can meet, what causes it and what to do, plus the codes that users and partners see as a result of staff actions.

Error shape

Every admin API error is JSON {"error": "<code>"}, with "fields": {"<field>": "<message>"} added for validation_failed (all problems at once). The code is stable and meant for programs; the message in fields is meant for people. HTTP status classes: 400 the request is wrong, 401 sign in again, 403 not allowed, 404 not found, 409 conflicts with the current state, 429 slow down, 503 a dependency is down.

HTTP/1.1 400 Bad Request

{
  "error": "validation_failed",
  "fields": {
    "reason": "required when suspending or deleting (3-500 characters); it is kept in the audit log"
  }
}

Answers that are not in the standard shape

  • GET /admin/api/v1/users/{id} with an id that is not a UUID answers 400 with Spring's default body {"timestamp": ..., "status": 400, "error": "Bad Request", "path": ...} (verified). Handle 400 without relying on error being a code.
  • 429 from the gateway and 404 from the health-probe proxy are HTML pages.
  • A revoked session token answers 401 with {"error":"unauthorized"} from the admin API, but the user API's gateway check answers 401 with an empty body.
