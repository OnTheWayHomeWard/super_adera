Moderation: reports

Work the queue of user reports about mini apps: list and filter, mark REVIEWED or DISMISSED, reopen, and see who handled what.

Overview

A report is a user telling Adera that a mini app is a problem (from the three-dot menu in the app window). Staff work the reports queue: read the reason and details, decide, and mark the report. In the backoffice: Moderation, tab Reports (default filter OPEN), the tab Reports of an app, and the Open reports panel on the Dashboard.

What a report does and does not do

A report is a signal to a human. It does not pause, hide or kill the app by itself. To act on the app (pause or kill it) use the app status control in the mini-app administration guide; then record the outcome here.

How a report is created (user side, for context)

POST /api/v1/apps/{idOrSlug}/report with a user session and a body {"reason":"SPAM|SCAM|INAPPROPRIATE|BROKEN|OTHER","details":"up to 2000 characters"}. The app must be LIVE. If the same user already has an OPEN report for the same app, a new request returns that report instead of adding another (verified: a second report with a different reason returned the same reportId), so a user cannot pile up reports; once staff marked it REVIEWED or DISMISSED the user can file a new one.

HTTP/1.1 200 OK

{
  "status": "received",
  "reportId": "347e2491-c20e-402e-b881-6773d4a744be"
}

Handle a report

PATCH/admin/api/v1/reports/{reportId}Mark a report REVIEWED, DISMISSED, or reopen it (OPEN)
Why
Close the loop: tell the team that someone looked at it and what the outcome was.
Auth
Staff aal2 Bearer, role ADMIN or SUPER_ADMIN
Audit action
report.handle (target type app_report, meta {status, appId, reason?})
Reversible
Yes: any status can be set from any status
Backoffice
Moderation > Reports: Resolve (REVIEWED), Dismiss (DISMISSED, asks for confirmation), Reopen (OPEN)

Body

FieldTypeRequiredConstraintsWhy it exists
statusstringyesOPEN, REVIEWED, DISMISSED (any case)The outcome.
reasonstringnoOptional text, max 500 charactersWhy you did it, at most 500 characters (longer: 400 validation_failed, fields.reason). Stored as handlingReason, returned in the admin lists, written to the audit entry as meta.reason; never shown to users.

Other fields in the body are ignored.

Reopen clears the handler

Setting OPEN clears handledBy and handledAt (both null again, as for any report nobody has handled). The audit entry report.handle with status: OPEN records who reopened it and when.

Two different fields: reason in the response is the user's category (SPAM, SCAM, ...); handlingReason is the staff note you sent as reason in the PATCH. It is also returned by GET /admin/api/v1/reports, written to the audit entry (meta.reason) and never shown to users. Each PATCH replaces the stored note (a reopen without a reason clears it); the audit log keeps every earlier one.

Errors (verified)

HTTP/1.1 400 Bad Request

{
  "error": "validation_failed",
  "fields": {
    "status": "must be OPEN, REVIEWED or DISMISSED"
  }
}

403 insufficient_role for a viewer, 404 not_found for an unknown id, 400 invalid_request for a non-UUID id.

Side effects

The report row is updated (status, handledBy = your staff id, handledAt = now) and one audit row is written. Setting the same status again re-stamps the handler and writes another audit row. The reporting user and the app's publisher are not notified; the app itself is not changed.

Statuses and reopen rules

StatusMeaningSet byCounted as work?
OPENFiled and waiting (also what a reopened report becomes)The system when the user files it; staff by reopeningYes: Dashboard reports.open
REVIEWEDStaff looked and acted (or confirmed the problem)ADMIN or SUPER_ADMINNo
DISMISSEDStaff looked and no action was neededADMIN or SUPER_ADMINNo

There is no workflow: staff may move a report between any two statuses at any time (verified OPEN to REVIEWED to OPEN to DISMISSED on one report). Each move is audited, so the audit log is the history. A user whose report is OPEN cannot add a second one for the same app; once it is REVIEWED or DISMISSED they can.

Worked scenario

Three open reports arrive for the same app with reason SCAM. In Moderation > Reports you open the app (link) and decide it is a real scam: you pause or kill the app in the app administration (the guide for mini-app administration), then press Resolve on each report. If a report turns out to be a user mistake, press Dismiss. The Dashboard's Open reports counter drops accordingly.

Not built yet

  • No notification to the reporter or the app publisher.
  • No automatic action when several reports arrive (no auto-pause).
