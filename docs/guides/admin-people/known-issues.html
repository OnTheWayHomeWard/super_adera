Known issues and not built yet

Bugs and inconsistencies found while verifying the admin API for this guide, with how to reproduce them, and the features that do not exist yet.

Known issues found while writing this guide

#IssueRepro / evidenceSeverity
1GET /admin/api/v1/users/notauuid returns Spring's default 400 body, not {"error": ...}.Repro: call it with any non-UUID id. Verified answer: {"timestamp":...,"status":400,"error":"Bad Request","path":...}. The other services answer invalid_request.Low
2Fixed 2026-10-26: reopening a report (status OPEN) now clears handledBy and handledAt (both null again); the move is still audited. A migration cleared the leftovers on existing OPEN reports.PATCH a report to REVIEWED, then OPEN: the response has both fields null.Low
3Fixed 2026-10-26: hiding or restoring a review and handling a report now accept an optional reason (max 500 characters). It is stored (moderationReason on reviews, handlingReason on reports), returned in the admin views, written to the audit meta, shown in the backoffice, and never exposed to users.Send {"status":"HIDDEN","reason":"spam"}: the response, the admin list and the audit entry carry it. More than 500 characters: 400 validation_failed with fields.reason.Fixed
4Fixed 2026-10-26: template changes are now audited. Creating a template writes template.create and editing, activating, deactivating or expiring one writes template.update (target type template, target id the template id; the entry records the staff id, role, client address and, for edits, which fields changed). If the audit entry cannot be written the change is undone and the call answers 503 audit_unavailable.Create or edit a template, then GET /admin/api/v1/audit?targetType=template (verified live).None needed.Fixed
5limit.set audit events store the limits as a text rendering of a Java object.Repro: GET /audit?action=limit.set&limit=1: meta.limits is "LimitRow[channel=IN_APP, maxPerUserPerDay=null, ...]" instead of a JSON object.Low
6A filter with an unknown status is accepted silently on reports and notifications, but rejected on reviews and users.Repro: GET /reports?status=bogus and GET /notification/notifications?status=BOGUS answer 200 []; GET /reviews?status=bogus and GET /users?status=bogus answer 400. A typo looks like an empty queue.Low
7A VIEWER can learn whether a given phone or email is registered.Repro: as a viewer GET /users?q=+251900000011 finds and shows the masked row. Search runs on unmasked data by design.Decide whether this is acceptable
8GET /notification/usage uses snake_case keys (distinct_users_today) while the whole API uses camelCase.Repro: GET /notification/usage?appId=....Low
9X-Total-Count is not exposed to other-origin browsers.The gateway CORS config exposes only X-Request-Id. The backoffice is same-origin so it works; a web client on another origin cannot read the totals of reviews, reports, audit and notifications.Low (matters for external web clients)
10GET /apps/{appId}/reviews answers 200 [] for an unknown app and has no total, unlike GET /reviews?appId=.Repro: call it with a random UUID.Low
11POST /staff ignores unknown body fields while PATCH /staff/{id} rejects them.Repro: add "foo":1 to the POST body: accepted.Low
12last_super_admin cannot be triggered through the API in practice.The caller must be an active super admin and cannot target themselves, so two active super admins always exist when the check runs. It is a safety net, not a bug.Info

Tooling gotcha (dev stack)

python3 -I tests/e2e/tempstaff.py clean removes every tempstaff-*@adera.local account, including one that another script or person is using at that moment (their Kratos identity and staff row disappear, so their token stops working). Run it only when nobody else is running e2e scripts. The login limit of 10 submits per minute per IP also makes parallel scripts fail with 429; they need to retry.

Not built yet (collected from all pages)

  • Erasing a user's personal data, or removing their Kratos identity, from the dashboard (DELETED is a flag).
  • Bulk user actions, user notes, profile editing by staff, login history.
  • A reason on review and report moderation; notes, assignment or notifications on reports.
  • A reset-authenticator button or API; an invitation email for new staff; deleting or filtering the staff list; changing a staff member's email.
  • Audit export, search inside meta, alerting, and audit of template changes, sign-ins and reads.
  • Search of notifications by recipient, re-send or cancel of a notification, visibility of the sign-in SMS and email log in the dashboard (it is in notification.send_log).
  • A build/version/uptime endpoint for the System page.
