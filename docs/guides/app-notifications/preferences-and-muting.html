Preferences and muting

The user can switch off in-app, SMS or email messages from each mini app separately. This page covers the switches and exactly what they stop.

Overview

Each user has three switches per mini app, the "3-dot menu" in the mini app window: muteInApp, muteSms, muteEmail. Default is all false (nothing muted). They exist so a user can silence one noisy mini app without leaving it or the platform. There are no global switches and no per-category switches today.

  "muteSms": false,
  "muteEmail": false

The answer is the full state after the change; render the toggles from it.

What a mute does

MomentEffect
When the partner sendsIf the channel that would be used is muted, the request is answered at once with 200 and status: SUPPRESSED, reason: recipient_opted_out. It is not queued and is not counted against the mini app's limits. Nothing is stored for the user.
When delivery runsThe mute is checked again (the user may have muted a moment after the request was accepted). If muted now, the status becomes SUPPRESSED and nothing is sent.
Channel matchingThe switch that applies is the one for the channel Adera chose: an IN_APP template follows muteInApp; a DIRECT template follows muteSms when it goes by SMS or muteEmail when it goes by email. Muting SMS does not redirect a DIRECT message to email: it is suppressed.
PushThere is no separate push switch: muteInApp stops the inbox item and the push together.
Existing itemsMuting does not delete or hide what is already in the inbox, and does not stop the mini app from running.
UnmutingTakes effect for the next notification. Suppressed ones are never replayed.

The partner learns only that the user "opted out" (SUPPRESSED); it cannot see which switch.

Not built yet

Notification categories and per-type settings (for example "order updates yes, promotions no"): the template category (TRANSACTIONAL, PROMOTIONAL, REMINDER) is stored but the user cannot filter by it. A global do-not-disturb and quiet hours do not exist either.
