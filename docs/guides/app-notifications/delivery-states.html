Delivery states

The status a partner sees for each notification, and what it means for the person on the other end.

Overview

The user never sees a status. Backend colleagues and support do, through the partner's status call, the callback and the staff tools. This page translates each status into what the user experienced, so a complaint ("I never got it") can be traced.

StatusFinal?Reason valuesWhat the user experienced
QUEUEDno-Nothing yet. Becomes SENT or a failure within about a second normally.
PROCESSINGno-Being delivered right now (a worker holds it for up to 60 s; if the worker dies it is picked up again).
RETRYINGnouser_directory_unavailable, or a temporary SMS/email provider codeNothing yet. Retried with backoff (30 s doubling to 1 h) up to 8 attempts or until the message expires.
SENTyes-IN_APP: the inbox item exists and a push was attempted on each device (push may have been skipped or failed: see the attempt log). SMS/EMAIL: handed to the provider.
SUPPRESSEDyesrecipient_opted_out, not_allowlistedNothing, by choice: the user muted that channel for the mini app, or (SMS/email only, real providers only) the recipient is not on the live allow-list. Not retried.
UNREACHABLEyesuser_unreachable, no_phone, no_emailNothing: the account was suspended or deleted after acceptance, or the phone or email the chosen channel needed is gone.
FAILEDyestwilio_http_4xx, resend_http_4xx (permanent provider refusal), max_attempts:<reason>Nothing: the provider rejected the number or address, or all 8 attempts failed.
EXPIREDyesthe last retry reason, or expiredNothing: the partner's ttlSeconds ran out (default 24 h, max 7 days) before delivery succeeded.

Answered at the door

Some outcomes never create a queued notification: 422 user_unreachable, 403 capability_not_granted, 429 quota_exceeded, validation and template errors. The mute case is special: it returns 200 with SUPPRESSED immediately and a stored record.

Attempt log (IN_APP)

Outcome / error codeMeaning
OK (provider fcm-fake or fcm)A push was handed to the provider for one device. One row per device.
SKIPPED / no_devicesThe user had no active registered device: inbox only.
PERMANENT / token_unregisteredDead token; that device was deactivated.
TRANSIENT / push_unavailableFirebase unavailable for that device; not retried.

Note that in the IN_APP case SENT says the inbox item was written, not that a phone showed a banner. A Firebase-side delivery receipt does not exist.

Tracing "I did not get my notification"

  1. Find the notification by the partner's externalId (partner status call). Status SUPPRESSED with recipient_opted_out: the user muted the mini app (ask them to check the 3-dot menu).
  2. SENT but no banner: check the inbox (it should be there). If it is, the problem is push: no registered device, dead token, phone permissions, or the fake provider in dev.
  3. SENT and nothing in the inbox: check the user's id mapping (alias), and that the user is looking at the same account.
  4. UNREACHABLE or 422 user_unreachable: the account is suspended or deleted.
