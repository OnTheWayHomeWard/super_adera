Error codes

Every error a client can meet on the inbox, preference and device calls, plus the partner-side refusals that decide whether a user receives something.

Shape

Errors from our services are {"error": "code"}, with "fields" for validation_failed. Errors from the gateway are different: 401 has an empty body and 429 an HTML page. Always branch on the HTTP status first.

Calls made by the app

StatuserrorWhereWhenClient action
401(empty body)allMissing, expired or revoked session token; or a half-finished two-step loginSend the user to login
429(HTML page)allGateway rate limit: inbox 300/min per IP on route me-notifications; preferences and devices 300/min on route meBack off and retry; do not parse as JSON
503identity_service_unavailableallGateway could not reach the identity serviceRetry with backoff; keep the session
400invalid_requestinbox, preferencesA query or path value of the wrong type (unread=abc, size=x, non-UUID id or appId), or an unreadable JSON bodyClient bug
404not_foundPUT /me/notifications/{id}/readUnknown item id or an item of another userRemove the row
400validation_failedPUT /me/apps/{appId}/preferences; PUT and DELETE /me/devicesUnknown field, non-boolean value, or (devices delete) neither fcmToken nor installationId given. fields names the offenderClient bug

Examples (captured): {"error":"validation_failed","fields":{"muteEverything":"unknown field"}} and {"error":"validation_failed","fields":{"fcmToken":"give fcmToken or installationId"}}.

Unsuccessful states that are not errors: an empty list is 200 []; marking an already-read item read is 200; removing a device that is not registered is 200 {"removed": 0}.

Partner-side refusals (for backend colleagues)

These are returned to the partner on POST /v1/notifications; the user sees nothing in every case. Signature and key errors are covered in the Partner API guide.
