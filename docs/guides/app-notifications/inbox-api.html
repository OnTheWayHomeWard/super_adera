Inbox API

The endpoints behind the bell icon: list the user's in-app notifications, count the unread ones, mark one or all as read.

Overview

Every IN_APP notification that was delivered becomes one inbox item for that user. Items are stored by Adera (not on the phone), so a reinstall or a second device sees the same list. All four endpoints are served by the notification service behind the gateway route me-notifications.

FactValue
Authuser session: Authorization: Bearer $TOKEN (the Kratos session_token). The gateway checks it and injects the user id; a client can never read or change another user's inbox
Rate limit300 requests per 60 seconds per client IP (gateway route me-notifications); over the limit the gateway answers 429 with an HTML page
OrderingNewest first (createdAt descending).
RetentionNone today: items are never deleted or expired and there is no delete call (see Not built yet).
ScopeItems of all mini apps together; filter by appId on the client.
What is not an itemSMS and email notifications (DIRECT templates) and notifications suppressed by a mute.

The inbox item

FieldTypeMeaning
idUUIDThe inbox item id; use it for mark-read. Unique per item. Not the partner's notification id.
appIdUUIDThe mini app that sent it; the same id the app catalog uses. Use it to show the app's name and icon and to open the mini app.
titlestringRendered title in the user's language (at most 100 characters). Always present for IN_APP.
bodystringRendered body (at most 1000 characters). Plain text; render it as text, never as HTML.
datastring (JSON)The partner's data object, encoded as a JSON string; "{}" when the partner sent none. Decode it with a JSON parser. Maximum 2048 bytes. The key order is not preserved (it is normalised by the database), so do not rely on it. Contents are defined by each mini app; see Building the bell screen.
createdAttimestamp (UTC)When the item was added to the inbox (delivery time, not the partner's request time).
readAttimestamp or nullnull means unread. Set once by mark-read and never changed afterwards.
GET/api/v1/me/notificationsList my notifications
Purpose / why
Fill the bell screen. Supports an unread-only view for the "Unread" tab and paging so a long history is not downloaded at once.
Who

Query parameters

NameTypeRequiredDefaultConstraintsWhy
unreadbooleannofalsetrue or false; anything else is 400 invalid_requestShow only items with readAt = null.
pageintegerno00-based; negative values are treated as 0Offset paging: items skipped = page * size.
sizeintegerno20clamped to 1..100 (0 becomes 1, 500 becomes 100); non-numeric is 400 invalid_requestPage length.

Example request

curl -s "$GATEWAY/api/v1/me/notifications?unread=true&size=1&page=0" \
  -H "Authorization: Bearer $TOKEN"

Response 200

[
  {
    "id": "f0560f1e-94f5-44f0-8dbb-72dec99bffb1",
    "appId": "24daadb5-f356-416d-8b91-43f5e6be386b",
    "title": "ትዕዛዝዎ በመንገድ ላይ ነው",
    "body": "ሰላም Selam፣ በ3 min ውስጥ ይደርሳል።",
    "data": "{\"n\": 5, \"meta\": {\"a\": 1}, \"screen\": \"order\", \"orderId\": \"1042\"}",
    "createdAt": "2026-10-26T10:50:35.430Z",
    "readAt": null
  }
]

The body is a bare JSON array (no wrapper, no total). Past the last page the answer is 200 []. Items from earlier pages:

GET /api/v1/me/notifications?page=9          ->  200  []

Using the result

  • Stop paging when a page returns fewer than size items (or an empty array).
  • New items arrive at the top while the user pages, which shifts later pages by one: de-duplicate by id when appending.
  • Show an unread dot when readAt == null.

Errors

StatuserrorWhenWhat the caller should do
400invalid_requestA query or path value has the wrong type (unread=abc, size=x, an id that is not a UUID).Fix the request; this is a client bug.
401(empty body)Missing, expired, revoked or malformed session token (also an account with an authenticator app that only finished the first login step). Produced by the gateway.Send the user to login, then retry.
429(HTML page)Gateway rate limit exceeded. Not JSON; check the status code before parsing the body.Back off (a few seconds) and retry; do not poll faster than the limit.
503identity_service_unavailableThe identity service could not be reached while the gateway checked the token.Keep the session, retry with backoff.
GET/api/v1/me/notifications/unread-countCount unread notifications
Purpose / why
A cheap number for the bell badge and the app-icon badge, so the client need not download the list just to show a dot.
Who
user session: Authorization: Bearer $TOKEN (the Kratos session_token). The gateway checks it and injects the user id; a client can never read or change another user's inbox
Rate limit
300 requests per 60 seconds per client IP (gateway route me-notifications); over the limit the gateway answers 429 with an HTML page

Parameters

None.

Example

curl -s "$GATEWAY/api/v1/me/notifications/unread-count" -H "Authorization: Bearer $TOKEN"
HTTP/1.1 200 OK

{
  "count": 1
}

count is a number over all the user's items (all mini apps); it is exact, not capped. There is no per-app count.

PUT/api/v1/me/notifications/{id}/readMark one notification as read
Purpose / why
Clear the unread state when the user opens an item. Idempotent so the client may retry or send it twice.
Who
user session: Authorization: Bearer $TOKEN (the Kratos session_token). The gateway checks it and injects the user id; a client can never read or change another user's inbox
Rate limit
300 requests per 60 seconds per client IP (gateway route me-notifications); over the limit the gateway answers 429 with an HTML page

Path parameter

NameTypeRequiredWhy
idUUIDyesThe inbox item id from the list.

Example

curl -s -X PUT "$GATEWAY/api/v1/me/notifications/$ITEM_ID/read" -H "Authorization: Bearer $TOKEN"
HTTP/1.1 200 OK

{
  "read": true,
  "id": "f0560f1e-94f5-44f0-8dbb-72dec99bffb1"
}

Calling it again returns the same 200 and the original readAt is kept. There is no body to send and no way to mark an item unread again.

PUT/api/v1/me/notifications/read-allMark all notifications as read
Purpose / why
The "Mark all as read" button. One call instead of one per item.
Who
user session: Authorization: Bearer $TOKEN (the Kratos session_token). The gateway checks it and injects the user id; a client can never read or change another user's inbox
Rate limit
300 requests per 60 seconds per client IP (gateway route me-notifications); over the limit the gateway answers 429 with an HTML page

Parameters

None (no body).

Example

curl -s -X PUT "$GATEWAY/api/v1/me/notifications/read-all" -H "Authorization: Bearer $TOKEN"
HTTP/1.1 200 OK

{
  "markedRead": 1
}

markedRead is the number of items that were unread; a second call returns {"markedRead": 0}. Items that arrive after the call stay unread. It marks every mini app's items; there is no per-app variant.
