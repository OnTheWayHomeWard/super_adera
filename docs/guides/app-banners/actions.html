Handling a tap

What the app does for each action type.

Overview

The server validated actionType and target when staff saved the banner, so the values have a known shape. The app still treats them as data: it never runs or evaluates them, and it only opens what the rules below allow.

actionTypetargetWhat the app does
MINI_APPA route starting with /, or nullOpens the linked mini app (app) through the normal launch, then navigates it to target (or its home when null).
INTERNALadera://...Opens the super-app screen for that link (your own deep-link router).
EXTERNALhttps://... on an approved domainOpens the page in the system browser or an in-app browser tab.
NONEnullNothing; do not show a pressed state.

MINI_APP: open a mini app at a page

  1. The user must be signed in (a launch needs the user's session). If the banner was tapped before sign-in, sign in first, then continue.
  2. Launch app.slug exactly as if the user had opened it from the catalog: POST /api/v1/me/apps/{app}/launch, with consent and the launch token working as usual. The banner gives the mini app no extra rights.
  3. The launch answer's url is the app's registered address with ?launch=<token>. Put the route into the path of that address and keep its query: https://www.zayride.com?launch=eyJ... with target /promo/first-ride becomes https://www.zayride.com/promo/first-ride?launch=eyJ.... Join the paths so there is exactly one / between them. The host never changes: a target is always a path (the server refuses anything else, including //host).
  4. With a null target, load url as it is (the app's home).
  5. If the launch is refused (403 app_not_live: the app was suspended a moment ago), show the usual "app unavailable" message.

INTERNAL: a super-app screen

Hand target to the app's deep-link router (the same one that handles adera:// links from notifications). An unknown link (an older app version that does not have that screen yet) does nothing, or opens the home screen; never crash.

Links in use are agreed between staff and the app team (for example adera://wallet). The server only checks the adera:// prefix and the characters, not that the screen exists.

EXTERNAL: a web page

  • Open in the system browser or an in-app browser tab (Custom Tabs, SFSafariViewController), never inside a mini-app WebView and never with the user's session or the bridge.
  • The server accepted the URL only if it is https:// and its host is on the operators' allow-list. Check https:// again before opening as defence in depth.

NONE

An image-only banner (an announcement). Not tappable.

Analytics (suggestion)

Record "shown" when at least half of a banner was on screen for a second and "tapped" on tap, with the banner id, placement and position. There is no server endpoint for these events yet.
