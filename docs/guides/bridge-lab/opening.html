Opening it from the super app

How a phone reaches Bridge Lab on the laptop, and what the super app must do when the user opens it.

Overview

Bridge Lab is listed in the catalog like any LIVE mini app. Opening it must go through the launch endpoint: that is the first thing the tests check.

Steps

  1. Seed and start Bridge Lab (previous page).
  2. Phone on USB or an emulator: adb reverse tcp:8095 tcp:8095 and adb reverse tcp:8096 tcp:8096, plus whatever you already reverse for the gateway (usually tcp:9080).
  3. Sign in to the super app with a test user. On the dev stack: +251900000001 with the password kebede ("Demo Abebe"). A fresh user is better for the tests that need a permission that was never asked.
  4. Open Bridge Lab from the catalog.

What the super app must do on opening

POST $GATEWAY/api/v1/me/apps/bridge-lab/launch
Authorization: Bearer $TOKEN

HTTP 200
{
  "launchToken": "eyJhbGciOiJSUzI1NiIs...",
  "expiresInSeconds": 300,
  "url": "http://localhost:8095/?entry=1&launch=eyJhbGciOiJSUzI1NiIs...",
  "consents": [ ... ]
}

Load url exactly as returned in the WebView, show no dialog, inject window.adera for this origin. The entry=1 part is the registered address's own query: test L02 checks that it was kept and that the token was appended with &.

What you see

The header shows the user's pseudonymous id (verified by Bridge Lab's backend against the Adera public key), whether window.adera was found, and the progress count. If the page was opened at a deep-link route a notice points at the deep-link tests.

Without the bridge

The page also opens in a normal browser at http://localhost:8095/?entry=1. Then almost every test ends in Not developed yet with the exact thing the super app must build, which is useful in itself as a checklist.
