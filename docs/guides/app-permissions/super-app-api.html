Super app: the user API

The seven endpoints the Adera app calls for permissions and for opening a mini app, with real requests and answers.

Overview

These are the seven endpoints the Adera app calls. All are served through the gateway for a signed-in user. They live under /me/apps/{app}, so they do not collide with the public catalog's /apps/{app}/permissions (what an app is allowed to use, visible to anyone). The mini app's page never calls them: it asks the bridge, and the super app calls them on its behalf with the user's session.

EndpointCalled whenLimit
POST /api/v1/me/apps/{app}/launchThe user opens a mini app60 / minute
POST .../permissions/{capability}/requestrequestPermission30 / minute
PUT .../permissions/{capability}/answerThe user taps Allow or Deny300 / minute
GET .../permissionsThe menu sheet, getPermission300 / minute
PUT .../permissions/{capability}A switch in the menu sheet300 / minute
DELETE .../permissionsThe Disconnect button300 / minute
GET /api/v1/me/permissionsThe settings screen300 / minute

The dialog sequence

  1. The mini app calls adera.requestPermission("location.fine").
  2. The super app calls request. If the answer has no prompt, it resolves the Promise with the state and stops.
  3. Otherwise it shows the dialog (label and purpose verbatim; Allow / Deny).
  4. It calls answer with the promptId and the choice, and resolves the Promise with the new state.
  5. For location, the phone's own dialog follows (the first time); Adera only records the user's consent.

How to use it

  • canAskAgain is true when a dialog would be shown on the next request (NOT_ASKED or DENIED).
  • Capabilities staff removed are not listed; the user's earlier answer is kept but inert, and applies again if staff grant the capability again.
  • Read on every opening of the sheet: pausing the app or removing a grant takes effect at once.
POST/api/v1/me/apps/{app}/permissions/{capability}/requestThe mini app needs a permission now
Who may call
The signed-in user (the super app, from requestPermission)
Auth
Authorization: Bearer $TOKEN (the user's session token)
Rate limit
30 per minute per client address (stricter than the rest: each call can open a dialog)

Purpose. Returns the state and, only when a dialog is allowed (NOT_ASKED or DENIED), a one-time prompt with the approved text. GRANTED and BLOCKED return prompt: null; a capability staff did not grant returns NOT_AVAILABLE at once. A new request replaces an older open prompt.

NameWhereTypeRequiredMeaning
apppathstringyesThe mini app's id (UUID) or its slug (for example demo-ride). The app must be LIVE.
capabilitypathstringyesA capability key such as location.fine (lower-case letters, digits, _ and .). The staff must have granted it to the app.

First request: a dialog is allowed (real)

How to use it

  • Show the dialog only if prompt is not null, with label and purpose verbatim, then send the answer with the promptId.
  • The prompt lives 5 minutes (expiresInSeconds) and works once.
  • The mini app should explain itself before asking a second time (state DENIED): a second refusal blocks.
PUT/api/v1/me/apps/{app}/permissions/{capability}/answerThe user's answer in the dialog
Who may call
The signed-in user (the super app)
Auth
Authorization: Bearer $TOKEN (the user's session token)
Rate limit
300 per minute per client address

Purpose. Records the dialog's answer. Accepted only with the one-time promptId from the request call for this user, app and capability, within 5 minutes, once. Allow sets GRANTED (denial count 0). The first Deny sets DENIED (count 1), the second in a row BLOCKED (count 2).

NameWhereTypeRequiredMeaning
apppathstringyesThe mini app's id (UUID) or its slug (for example demo-ride). The app must be LIVE.
capabilitypathstringyesA capability key such as location.fine (lower-case letters, digits, _ and .). The staff must have granted it to the app.
promptIdbodystringyesThe id from the request call. The server issues it, so a bridge cannot invent an answer.
answerbodystringyesGRANTED or DENIED.

How to use it

  • Every answer appends a row to the append-only proof table (consent_event): who, which capability, from and to which state, when, and how (dialog or menu).
  • canAskAgain is true only for DENIED.
PUT/api/v1/me/apps/{app}/permissions/{capability}Menu switch: allow or deny, also unblocks
Who may call
The signed-in user (the menu sheet)
Auth
Authorization: Bearer $TOKEN (the user's session token)
Rate limit
300 per minute per client address

Purpose. The switch in the mini app's top menu. It always works, needs no prompt, resets the denial count and is the only way out of BLOCKED. On sets GRANTED; off sets DENIED with count 0 (the mini app may ask again later). Any open prompt is closed.

statebodystringyesGRANTED or DENIED.

DELETE/api/v1/me/apps/{app}/permissionsDisconnect: take everything back
Who may call
The signed-in user (the Disconnect button)
Auth
Authorization: Bearer $TOKEN (the user's session token)
Rate limit
300 per minute per client address

Purpose. Everything the user allowed the app becomes DENIED with count 0 (a BLOCKED one too), user.basic included, and any open prompt is closed. Never-asked permissions stay NOT_ASKED. Repeatable (nothing left to change gives an empty changed). Works on paused and killed apps too: the user can always leave. The partner receives a user.disconnected callback if staff set a callback address.

NameWhereTypeRequiredMeaning
apppathstringyesThe mini app's id (UUID) or its slug (for example demo-ride). The app must be LIVE.

POST/api/v1/me/apps/{app}/launchOpen a mini app: launch token, URL and states
Who may call
The signed-in user (the super app, when the user opens a mini app)
Auth
Authorization: Bearer $TOKEN (the user's session token)
Rate limit
60 per minute per client address

Purpose. Opening a mini app. No dialog. Mints the user's pseudonymous id for this app (first time), reconnects it if the user had disconnected, and returns a five-minute RS256 launch token (signed with the Adera key), the URL to load (the registered URL with ?launch=<token>) and the user's current state per permission.

NameWhereTypeRequiredMeaning
apppathstringyesThe mini app's id (UUID) or its slug (for example demo-ride). The app must be LIVE.

How to use it

  • Load url in the WebView. If it is null (staff registered no URL) the app cannot be opened.
  • Call launch every time the mini app is opened; never cache a token.
  • Claims of the token and how a mini app verifies it: see "Mini app developers".

Not built yet

  • Consent expiry (it does not expire) and per-payment confirmation for pay.request (designed when payments are built).
