Location: share, update, clear

Share, update and clear the optional location in the profile: what is stored, coarse versus fine, and the exact validation.

Overview

The profile can hold one location that the person chose to share: a city/region/country, optionally with exact coordinates. Why it exists: so the app (and in the future mini apps that ask for it) can offer local content without asking every time. It is always user-initiated: the server never derives a location from an IP address and nothing is stored unless the app calls PUT /api/v1/me/location. Ask for the operating-system location permission first, then store only what you need.

Method and pathPurpose
PUT /api/v1/me/locationset (replace) the stored location
DELETE /api/v1/me/locationclear it
GET /api/v1/meread it, as the location object

What is stored: coarse versus fine

FieldTypeValidationNotes
countryCodestringexactly two letters (^[A-Za-z]{2}$); stored upper-caseany two letters pass: the server does not check the code against the ISO list
regionstringmax 100 charactersstate, province or sub-city (e.g. "Addis Ababa"); blank is stored as null
citystringmax 100 charactersblank is stored as null
latitudenumber-90 to 90give together with longitude or not at all
longitudenumber-180 to 180give together with latitude or not at all
updatedAttimestampset by the serverwhen the location was last set; present in the response only
  • Coarse = countryCode, region, city only. This is enough for almost every use and is what you should send by default.
  • Fine = also latitude and longitude. Only send them when a feature really needs a position (nearest branch, delivery address), and only after the person agreed. The server stores the numbers exactly as sent (9.0054 came back as 9.0054); it does not round them. Round on the device (for example to 2 decimals, about 1 km) if you only need the neighbourhood.
  • Staff screens show the country, region and city of a user and only a yes/no flag saying that precise coordinates exist; they do not show the coordinates.
  • At least one of country, region, city or the coordinate pair is required; an empty request is refused.

Endpoints

PUT/api/v1/me/locationShare (set) my location
Who may call
signed-in user, account not blocked
Auth
Authorization: Bearer $TOKEN
Headers
Content-Type: application/json
Rate limit
300 per 60 s per IP
Implemented by
ProfileController#setLocation, LocationRequest.java

Purpose

Stores the location, replacing whatever was stored before (it is a PUT, not a merge). Sending only a city after a full location erases the old region and coordinates (verified). To update one part, send the complete location you want to keep.

Parameters

JSON body with any of countryCode, region, city, latitude, longitude as in the table above. At least one meaningful value is required, and a latitude without a longitude (or the reverse) is refused.

Example request (fine location)

curl -s -X PUT "$GATEWAY/api/v1/me/location" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"countryCode":"et","region":"Addis Ababa","city":"Bole","latitude":9.0054,"longitude":38.7636}'

Example response

HTTP/1.1 200 OK
Content-Type: application/json

{
  "...": "all profile fields (id, firstName, ..., extra)",
  "location": {
    "countryCode": "ET",
    "region": "Addis Ababa",
    "city": "Bole",
    "latitude": 9.0054,
    "longitude": 38.7636,
    "updatedAt": "2026-10-26T10:50:05.998994084Z"
  },
  "updatedAt": "2026-10-26T10:50:05.998994084Z"
}

Coarse variant: {"city":"Hawassa","countryCode":"ET"} answers "location": {"countryCode":"ET","region":null,"city":"Hawassa","latitude":null,"longitude":null,"updatedAt":"..."}. Note the lower-case et was stored as ET.

Using it in the app

  • The answer is the whole profile; use location.updatedAt to show "last updated".
  • Call it when the person explicitly picks or confirms a place, not on every GPS fix: each call is a write and counts toward the 300 per minute limit.
  • Show where the stored location is visible (profile screen) and give a clear way to remove it.
DELETE/api/v1/me/locationClear my location
Who may call
signed-in user, account not blocked
Auth
Authorization: Bearer $TOKEN
Rate limit
300 per 60 s per IP
Implemented by
ProfileController#clearLocation

Purpose

Removes the stored location completely (all five values and the timestamp). Use it for a "stop sharing my location" switch. It is idempotent: clearing when nothing is stored also answers 200.

Example request

curl -s -X DELETE "$GATEWAY/api/v1/me/location" -H "Authorization: Bearer $TOKEN"

Example response

HTTP/1.1 200 OK
Content-Type: application/json

{
  "...": "all profile fields",
  "location": null,
  "updatedAt": "2026-10-26T10:50:06.132749479Z"
}
