Quick start: first run, copy and paste

A complete first-run sequence you can paste into a shell: sign up with a phone code, use the profile, location, device and avatar APIs, log out, and sign in again.

Before you start

  • A shell with curl and jq. The dev gateway is http://127.0.0.1:9080 ($GATEWAY).
  • The dev stack runs in dev mode: the SMS provider is the console (nothing is sent) and the notification service exposes /dev/messages so you can read the one-time code. In production the person receives the code by SMS or email and step 3 is replaced by the user typing it.
  • A small image file named photo.jpg in the current directory for the avatar step (any JPEG, PNG, GIF or BMP under 5 MiB).
  • Use a phone number of your own (international format). Every sign-in step counts against the gateway limit of 10 submits per minute per IP and the per-number SMS limit of 5 per hour, so do not run this in a loop.
  • The whole script below was run end to end against the dev stack on 2026-10-26 (registration, profile, location, device, avatar, logout, then a returning login); the outputs in this guide come from those runs.

First run: register, fill the profile, register the device, log out

Copy the block into a shell (it is plain bash). Each step prints what to look at. Variables set early ($TOKEN, $USER_ID) are reused by later steps.

export GATEWAY=http://127.0.0.1:9080
export PHONE='+2519XXXXXXXX'        # a number of your own, international format (any well-formed number works in dev)

# 1. Start a registration flow (valid 10 minutes)
FLOW=$(curl -s "$GATEWAY/kratos/self-service/registration/api" | jq -r .id)
echo "flow: $FLOW"

# 2. Submit the phone: Kratos sends the code. HTTP 400 with state "sent_email" is the SUCCESS answer.
curl -s -X POST "$GATEWAY/kratos/self-service/registration?flow=$FLOW" \
  -H 'Content-Type: application/json' \
  -d "{\"method\":\"code\",\"traits.phone_number\":\"$PHONE\"}" | jq '{state, message: .ui.messages[0].id}'

# 3. DEV ONLY: read the code the console SMS provider "sent" (in production the user receives an SMS)
sleep 2
CODE=$(curl -s "http://127.0.0.1:8085/dev/messages?to=$(jq -rn --arg p "$PHONE" '$p|@uri')" \
  | jq -r 'max_by(.at).body' | grep -oE '[0-9]{6}' | head -1)
echo "code: $CODE"

# 4. Submit phone + code: HTTP 200 returns the session token
RESP=$(curl -s -X POST "$GATEWAY/kratos/self-service/registration?flow=$FLOW" \
  -H 'Content-Type: application/json' \
  -d "{\"method\":\"code\",\"traits.phone_number\":\"$PHONE\",\"code\":\"$CODE\"}")
export TOKEN=$(echo "$RESP" | jq -r .session_token)
export USER_ID=$(echo "$RESP" | jq -r .session.identity.id)
echo "user id: $USER_ID   session expires: $(echo "$RESP" | jq -r .session.expires_at)"

# 5. Read my profile (the profile row was created by the registration web hook)
curl -s "$GATEWAY/api/v1/me" -H "Authorization: Bearer $TOKEN" | jq .

# 6. Fill in the profile (only the keys that change)
curl -s -X PATCH "$GATEWAY/api/v1/me" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"firstName":"Selam","lastName":"Tadesse","language":"am","termsAcceptedVersion":"2026-10","extra":{"ui":{"theme":"dark"}}}' \
  | jq '{firstName, language, termsAcceptedAt, extra}'

# 7. Share a coarse location, then clear it
curl -s -X PUT "$GATEWAY/api/v1/me/location" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"countryCode":"ET","city":"Addis Ababa"}' | jq .location
curl -s -X DELETE "$GATEWAY/api/v1/me/location" -H "Authorization: Bearer $TOKEN" | jq .location

# 8. Register this installation for push (use your real FCM token; any string works in dev)
curl -s -X PUT "$GATEWAY/api/v1/me/devices" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"fcmToken":"dev-fcm-token-1","platform":"ANDROID","installationId":"my-install-0001","appVersion":"1.0.0","deviceName":"Test phone"}' | jq .
curl -s "$GATEWAY/api/v1/me/devices" -H "Authorization: Bearer $TOKEN" | jq 'length'

# 9. Upload an avatar (any JPEG, PNG, GIF or BMP up to 5 MiB; the server crops/resizes to 512 px)
curl -s -X POST "$GATEWAY/api/v1/me/avatar" -H "Authorization: Bearer $TOKEN" -F "file=@photo.jpg" \
  | jq '{avatarImageId, avatarUrl}'
# show it: the avatarUrl is a signed link, fetch it WITHOUT the Authorization header
curl -s -o avatar.jpg "$(curl -s "$GATEWAY/api/v1/me" -H "Authorization: Bearer $TOKEN" | jq -r .avatarUrl)" && file avatar.jpg

# 10. Log out this device: removes the push token and revokes the session (HTTP 204)
curl -s -o /dev/null -w "logout: %{http_code}\n" -X POST "$GATEWAY/api/v1/me/logout" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"fcmToken":"dev-fcm-token-1","installationId":"my-install-0001"}'
# the old token is dead now (HTTP 401)
curl -s -o /dev/null -w "after logout: %{http_code}\n" "$GATEWAY/api/v1/me" -H "Authorization: Bearer $TOKEN"

What you should see: step 2 prints {"state":"sent_email","message":1040005} (the code was sent); step 4 prints the user id and the 30-day expiry; step 5 shows a fresh profile with firstName: null, language: "en", market: "ET", status: "ACTIVE"; step 6 shows the updated fields and termsAcceptedAt set by the server; step 7 prints the location then null; step 8 prints the device and 1; step 9 prints an avatarImageId, then file reports a 512x512 JPEG; logout prints 204 and the old token gives 401.

Second run: the same person signs in again

A returning user uses the login endpoints and the field identifier. The profile you saved is still there.

# Returning user: the same flow with the login endpoints and "identifier"
FLOW=$(curl -s "$GATEWAY/kratos/self-service/login/api" | jq -r .id)
curl -s -X POST "$GATEWAY/kratos/self-service/login?flow=$FLOW" \
  -H 'Content-Type: application/json' \
  -d "{\"method\":\"code\",\"identifier\":\"$PHONE\"}" | jq '{state, message: .ui.messages[0].id}'
# (dev) read the newest code for $PHONE as in step 3, then:
sleep 2
CODE=$(curl -s "http://127.0.0.1:8085/dev/messages?to=$(jq -rn --arg p "$PHONE" '$p|@uri')" \
  | jq -r 'max_by(.at).body' | grep -oE '[0-9]{6}' | head -1)
export TOKEN=$(curl -s -X POST "$GATEWAY/kratos/self-service/login?flow=$FLOW" \
  -H 'Content-Type: application/json' \
  -d "{\"method\":\"code\",\"identifier\":\"$PHONE\",\"code\":\"$CODE\"}" | jq -r .session_token)
curl -s "$GATEWAY/api/v1/me" -H "Authorization: Bearer $TOKEN" | jq '{id, firstName, language}'

Expected: {"state":"sent_email","message":1010014}, then {"id":"...","firstName":"Selam","language":"am"}. If the login flow answers message 4000035 instead, the number has no account: use the registration flow (the app should try login first, then fall back to registration; see Registration and login).

The same sequence as an app does it

  1. Launch: read the token from secure storage. None: show sign-in. Present: GET /api/v1/me. 200: go on. 401: delete the token, show sign-in. 403: blocking screen. 5xx/offline: retry, keep the token.
  2. Sign-in screen: ask for phone or email once. GET /kratos/self-service/login/api, POST the identifier. 4000035: switch to the registration flow with the same identifier. 1010014/1040005: show the code screen with a 5-minute countdown.
  3. Code screen: POST identifier plus code to the same flow. 200: store session_token (and session.expires_at). 400 with 4010008/4040003: wrong code, let them retry. 429: wait and retry.
  4. After sign-in: GET /api/v1/me; if firstName is null run onboarding (PATCH /api/v1/me, optional PUT /location, optional avatar).
  5. Push: get the FCM token and PUT /api/v1/me/devices (with a stored installation id); repeat on every token refresh.
  6. Sign out: POST /api/v1/me/logout with the FCM token and installation id, then clear local state.

Cleaning up after a test

The script logs the session out. The account itself stays (the platform has no customer-facing account deletion yet, see Known issues and not built yet). In the dev stack the test account can be removed by the platform owner; do not reuse the seeded demo accounts for experiments.
