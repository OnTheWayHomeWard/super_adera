Change password

Change the password of a signed-in user through the Kratos settings flow: the recent-login rule, the calls and the errors.

Overview

A signed-in user changes the password through Kratos' settings flow, with the same call that finishes a recovery. The profile method of the settings flow (changing the phone or email) is disabled; only the password can be changed here.

Recent login required

The settings flow needs a privileged session: one created in the last 15 minutes (privileged_session_max_age: 15m). A session made by login or by recovery counts from that moment. With an older session, creating or submitting the flow fails; ask the user for the password again: start a login flow with ?refresh=true sending the old token in X-Session-Token (Kratos then issues a refreshed session), then retry. After a recovery the session is privileged, so the new password can be set at once.

Call sequence

  1. GET /kratos/self-service/settings/api with the session token in the X-Session-Token header (or Authorization: Bearer): flow id. After a recovery the flow id comes from continue_with instead.
  2. POST /kratos/self-service/settings?flow=ID with {"method":"password","password":"..."} and the same token header.
  3. 200 with state: "success": changed. Other sessions of the account are signed out (revoke_active_sessions); the one used stays valid.

Example request
