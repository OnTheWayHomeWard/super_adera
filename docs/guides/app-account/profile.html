The profile API: /api/v1/me

Read and update the signed-in user's own profile: every field, what is editable, and exactly how each value is validated.

Overview

The profile is the person's own record in Adera: who they are, their language and market, an avatar, a location they chose to share, and a free-form extra object for app preferences. There is exactly one profile per account, it is created automatically at sign-up, and its id is the Kratos identity id (the same id the session returns). The app can only ever read and change its own profile: the user id comes from the verified token, never from the request.

Method and pathPurposePage
GET /api/v1/meread the profilethis page

PUT /api/v1/me/location, DELETE /api/v1/me/locationshare / clear a locationLocation
POST /api/v1/me/avatar, DELETE /api/v1/me/avatarset / remove the avatar pictureAvatar
PUT|GET|DELETE /api/v1/me/devicespush tokensDevices and push tokens
POST /api/v1/me/logoutsign this device outSession and logout

All of these need Authorization: Bearer $TOKEN, share the gateway limit of 300 requests per minute per IP (the avatar upload has its own 20 per minute) and answer in the error shapes listed on the Error table page. Every successful profile call returns the whole profile (same shape as GET), so the app can replace its local copy with each answer.

The profile object

FieldTypeEditableMeaning and notes
idUUID stringnothe user id (= Kratos identity id)
emailstring or nullnocopy of the email the account was registered with; null for phone accounts. Not editable here (it is the login identifier)
phonestring or nullnoE.164 phone the account was registered with; null for email accounts. Not editable here. Mask it when you display it near others
firstName, lastNamestring or nullyesup to 100 characters each; null until the person fills them in

languagestringyesen, am (Amharic) or om (Oromo); default en. The notification service renders messages for this user in this language, so keep it equal to the language the person picked in the app
marketstringyesET (Ethiopia) or US; default ET (US for a phone starting +1). The app passes it to the mini-app catalog (?market=) to list the apps offered in that market
timezonestringyesIANA name such as Africa/Addis_Ababa (default)
avatarImageIdUUID or nullvia avatar APIid of the stored picture; changes with every upload, so it is a good cache key
avatarUrlstring or nullvia avatar APIshort-lived signed link (60 minutes) to the picture; see Avatar
locationobject or nullvia location API{countryCode, region, city, latitude, longitude, updatedAt} or null when nothing is shared
verificationTierstringnoCONTACT (code-verified phone/email), ID, PROVIDER. Everyone is CONTACT today; no endpoint changes it
statusstringno (staff)ACTIVE, SUSPENDED or DELETED. A client normally only ever sees ACTIVE here, because the other two are refused with 403 before the profile is read (see Session and logout)
termsAcceptedVersion, termsAcceptedAtstring / timestamp or nullyes (version)which version of the terms the person accepted (up to 32 characters, chosen by the app) and when the server recorded it. termsAcceptedAt is set by the server
extraobjectyesfree-form JSON owned by the app; see Extra data
createdAt, updatedAttimestampnoISO-8601 UTC. updatedAt moves on every successful change (even an empty PATCH {})

Timestamps are UTC with a variable number of fractional digits (6 to 9); parse them with a tolerant ISO-8601 parser. Fields that are null are always present (never omitted).

Purpose

Returns the signed-in user's profile. It is the first call after sign-in: it tells the app who the user is, whether onboarding is complete, and the current avatar link. It also records that the person was seen recently (at most once every 5 minutes; not shown to the app). If the registration web hook ever failed, this call creates the missing profile from Kratos' record.

Parameters

None.

curl -s "$GATEWAY/api/v1/me" -H "Authorization: Bearer $TOKEN"

Using it in the app

  • Show onboarding when firstName is null (or your terms version is not yet accepted).
  • Cache the profile and refresh it on app start; do not poll it. Every PATCH, location and avatar call returns the fresh profile anyway.
  • A trailing slash (/api/v1/me/) is a 404 from the service: use the path exactly.

Purpose

Changes some fields of the profile. Send only what changes: a key that is absent is left alone; a key sent as null clears the field (where the field may be empty). All problems are validated first and reported together: if any field is invalid, nothing is saved. Unknown keys are rejected, so a typo cannot silently do nothing.

Request body (all fields optional)

FieldTypeValidationNull / blank
firstNamestringtrimmed, max 100 charactersnull or blank clears it (blank becomes null)
lastNamestringtrimmed, max 100 characterssame
genderstringone of MALE, FEMALE, OTHER, PREFER_NOT_TO_SAY, case-insensitive (female is stored as FEMALE)null clears
dateOfBirthstringISO date YYYY-MM-DD; not in the future, not before year 1900 (compared with today in UTC)null clears
languagestringam, en or om (case-insensitive, stored lower-case)cannot be cleared: null gives validation_failed
marketstringET or US (case-insensitive, stored upper-case)cannot be cleared
timezonestringa valid IANA zone id, e.g. Africa/Addis_Ababa, America/New_Yorkcannot be cleared
termsAcceptedVersionstringmax 32 charactersa non-null value stores the version and sets termsAcceptedAt to now (again on every PATCH that includes it); null clears both
extraobjecta JSON object, merged into the stored one (JSON Merge Patch), max 16384 bytes; see Extra datanull as the whole value is rejected; null inside it removes a key

Any other key (email, phone, status, id, avatarUrl, location, ...) is answered with "unknown field".

Example request

curl -s -X PATCH "$GATEWAY/api/v1/me" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Selam","lastName":"Tadesse","gender":"female","dateOfBirth":"1995-04-12","language":"am","timezone":"Africa/Addis_Ababa","termsAcceptedVersion":"2026-10","extra":{"occupation":"nurse","prefs":{"theme":"dark"}}}'

Example: clearing fields

curl -s -X PATCH "$GATEWAY/api/v1/me" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"lastName":null,"gender":null}'

Answer 200 with the whole profile where lastName and gender are null and everything else is unchanged (verified). Sending {"firstName":" "} also clears the first name (blank text becomes null).

Field messages are English developer text; key the UI on the field name and show your own message. Other messages seen: "max 100 characters" (first/last name), "must be an ISO date (YYYY-MM-DD)" (unparsable date such as 12/04/1995), "max 32 characters" (terms version).

Using it in the app

  • Send only the changed keys. An empty {} succeeds and only bumps updatedAt.
  • There is no version check: two devices editing the same scalar field overwrite each other (last write wins). extra merges key by key, so independent keys survive.
  • When the person changes the app language, PATCH {"language":"om"} so push messages follow.
  • Terms: send termsAcceptedVersion once, when the person accepts; resending refreshes termsAcceptedAt.
