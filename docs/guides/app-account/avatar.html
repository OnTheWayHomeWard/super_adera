Avatar: upload, read, delete

Upload, display and delete the profile picture: accepted files, the limits, what the server does to the image, and how the signed link works.

Overview

Each person can have one profile picture. The app uploads any normal photo; the server turns it into one small, safe square JPEG, stores it in object storage, and the profile then carries a short-lived signed link that the app uses to display it. Image bytes never travel through the API for reading: the app fetches the picture straight from storage with the link.

Method and pathPurpose
POST /api/v1/me/avatar (multipart)upload or replace the picture
DELETE /api/v1/me/avatarremove it
GET /api/v1/meread avatarImageId and avatarUrl

The upload has its own, stricter gateway limit: 20 per 60 s per IP (route me-avatar); the delete and the profile read use the normal 300 per minute.

What the server does with the picture

StepDetail
Accepted formatsJPEG, PNG, GIF, BMP. The server decodes the bytes; the file name and the declared Content-Type are ignored (a JPEG sent as image/png works, an HTML file labelled image/png is refused). WebP and HEIC/HEIF are not accepted (verified for WebP): convert iPhone HEIC photos to JPEG on the device before uploading
Size limitthe file may be at most 5 MiB (5242880 bytes) → 413 file_too_large. A hard transport limit of 6 MB per file / 7 MB per request also answers 413 file_too_large (verified with 5 MB + 1000 bytes and with 7 MB)
Dimension limitsat most 12000 pixels per side and 40 million pixels in total (protection against files that are tiny but decode to enormous bitmaps) → 400 "image dimensions are too large" (verified with a 13000x1 PNG)
Crop and resizecentre-cropped to a square, then scaled down so the side is at most 512 px. Smaller images are never enlarged. Verified: 900x600 gives 512x512; 300x900 gives 300x300; 100x100 stays 100x100
Re-encodingalways stored as image/jpeg, quality 85. Transparent PNG areas are flattened onto white. All metadata (EXIF location, camera, timestamps) is dropped. A multi-frame GIF keeps its first frame only
Orientationthe server does not read or apply the EXIF rotation flag and the flag is dropped with the other metadata. Make sure the pixels are upright before uploading (image pickers normally do). Not tested with a rotated sample
Replacinga new upload gets a new avatarImageId; the previous file is deleted from storage after the new one is saved
Storage keyavatars/<user id>/<image id>.jpg in the adera-media bucket. The bucket is private

Endpoints

POST/api/v1/me/avatarUpload or replace my avatar
Who may call
signed-in user, account not blocked
Auth
Authorization: Bearer $TOKEN
Headers
Content-Type: multipart/form-data; boundary=... (your HTTP client sets it when you use form upload)
Rate limit
20 per 60 s per IP (route me-avatar)
Implemented by
ProfileController#uploadAvatar, AvatarService, AvatarImageProcessor

Purpose

Sets the profile picture. Why multipart: it is the standard way for mobile HTTP clients to send a file, and it lets the server enforce the size before reading the body.

Parameters

NameInTypeRequiredConstraintsWhy
filemultipart form fieldbinaryyesfield name exactly file; non-empty; JPEG, PNG, GIF or BMP; at most 5 MiBthe picture

Example request

curl -s -X POST "$GATEWAY/api/v1/me/avatar" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@me.jpg"

Example response

HTTP/1.1 200 OK
Content-Type: application/json

{
  "...": "all profile fields",
  "avatarImageId": "2a9568e4-b7bb-4a5d-ba54-e98139bace33",
  "avatarUrl": "http://127.0.0.1:9000/adera-media/avatars/5bc6d545-771d-44f5-91cb-55415b01e4e4/2a9568e4-b7bb-4a5d-ba54-e98139bace33.jpg?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Date=20261026T105006Z&X-Amz-SignedHeaders=host&X-Amz-Credential=<access-key>%2F20261026%2Fus-east-1%2Fs3%2Faws4_request&X-Amz-Expires=3600&X-Amz-Signature=<signature>",
  "updatedAt": "2026-10-26T10:50:06.369381710Z"
}

The credential and signature in avatarUrl are masked here. The whole profile is returned, so the app can update its cache in one step.

Using it in the app

  • Downscale and compress on the device before uploading (long side about 1024 px, JPEG): less data on slow mobile networks, and no chance of hitting the size or dimension limits.
  • Show the upload progress, then replace the displayed picture with the new avatarUrl.
  • A failed upload leaves the old picture in place.

Purpose

Deletes the stored picture and clears avatarImageId and avatarUrl. Idempotent: removing when there is no avatar answers 200 too.

Showing the avatar: the signed URL

The profile's avatarUrl is an S3 pre-signed GET link to the object storage. What the app needs to know:

TopicDetail
Shape<storage host>/adera-media/avatars/<user id>/<image id>.jpg?X-Amz-Algorithm=...&X-Amz-Expires=3600&X-Amz-Signature=.... In the dev stack the host is http://127.0.0.1:9000 (RustFS); in a deployment it is the public storage address that phones can reach. Always use the URL exactly as returned (the host is part of the signature)
Expiry60 minutes (X-Amz-Expires=3600; server setting STORAGE_PRESIGN_MINUTES). After that the storage answers 403
No auth headerfetch it with a plain GET and do not add the Authorization header (it is not an API call, and the session token must never go to the storage host). Verified: the link returned 200, Content-Type: image/jpeg, 4726 bytes for a 512x512 picture
Not publicthe same path without the query string answers 403 (verified): only a fresh signed link works
Changes on every readeach profile answer contains a newly signed URL (different date and signature) for the same picture. Do not use the URL as a cache key; use avatarImageId (it changes only when the picture changes)
When the URL has expiredif loading fails with 403, call GET /api/v1/me once to get a fresh link and retry; do not loop
Whose pictureonly your own avatar is exposed through this API; there is no endpoint to fetch another user's avatar

A good pattern: keep the picture in the image cache keyed by avatarImageId; show it from the cache; only when the id changes (or the cache is empty) use the current avatarUrl to download it once.
