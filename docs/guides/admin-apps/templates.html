Notification templates

The only messages a partner may send: how staff create, edit, activate and expire them.

Overview

A template is a message a partner is allowed to send: the words in up to three languages, plus a short list of declared values the partner fills in (a name, a code, an order number). Only staff create and change templates. A partner's request says "send template X to user Y with these values"; it can never send free text.

Why this existsNotifications arrive under Adera's name, by SMS, email and push, to real people. If partners could write the text, an app could send phishing links or spam in an official voice. Admin approval means every sentence that can be sent was written or reviewed by Adera staff, in the right languages, and the only things a partner controls are small, length-limited, link-checked values. It also makes costs predictable (an SMS template has a known maximum length).

Anatomy of a template

Placeholders and values

  • In any text, {name} is replaced by the partner's value for the declared param name. Using {x} without declaring x in params is refused when you save.
  • A value must be text, a number or a boolean; it is trimmed; it may not be longer than its maxLength; it may not contain control characters; a required value may not be empty. Sending a value that is not declared is refused too.
  • Links are refused inside values unless the param has allowLinks: true. The check looks for http:, https:, www., :// and domain-like words ending in common endings (.com, .et, .app, ...). This stops a "name" field from carrying a phishing link. The template's own text (which you write) may contain links.
  • The user's language is chosen from the user profile; any text missing in that language falls back to the English text text by text (so an Amharic template with only a title still gets the English body).

What a refused value looks like to the partner (their call, checked at acceptance, 422):

HTTP 422  {"error": "param_invalid", "fields": {"name": "links are not allowed in this value"}}

Which channel and capability

KindDelivered asCapability required
IN_APPAn inbox entry in the Adera app plus a push to the user's devices (the inbox is the reliable part, push is best effort).notify.inapp
DIRECTSMS (the sms text) if the user has a phone and notify.sms is granted; otherwise email if the user has an email and notify.email is granted.notify.sms and/or notify.email

Usability, version, retiring

  • A template is usable now when it is active and the current time is inside its window. The views show usableNow and, when not usable, unusableReason: template_inactive, template_not_yet_valid or template_expired. A partner who sends an unusable template gets that code as 422.
  • version starts at 1 and goes up by one every time params or content change (not for active, category or window changes). Each notification records the version it was accepted with. The words used at delivery time are the template's current words, so an edit also changes messages that are accepted but not yet delivered.
  • There is no delete. To retire a template: set active: false (switch off, easy to undo) or set expiresAt to a time in the past or the end date of a campaign. See the retire runbook.
Watch out

Template changes are not written to the audit log (the notification service has no audit writer). Keep your own record of who changed which template; see Known issues.

Scenario

A food partner wants "Your order {orderNo} is on its way" in English and Amharic. You create order-on-the-way as IN_APP, TRANSACTIONAL, with the declared value orderNo (maxLength 20), check the wording with the partner, and give them the template id.

PATCH/admin/api/v1/notification/templates/{id}Edit, activate, deactivate or expire a template
Who may call
ADMIN or SUPER_ADMIN
Auth
Staff session Bearer token at assurance level aal2 (Authorization: Bearer $TOKEN)
Rate limit
300 requests per minute per client IP at the gateway (HTTP 429 beyond that)
Backoffice
App > Templates > Edit, and Deactivate / Activate on the row (confirmation: "Partner sends using this template are refused (template_inactive) until it is activated again")
Audit name
template.create / template.update
Reversible
Yes: patch the old values back

Purpose. Changes a template: the words, the declared values, the category, the validity window, or switches it on or off. When to use it. To fix wording, add a translation, start or stop a campaign, retire a template.

Body (all optional, but at least one)

FieldRules
contentReplaces all languages and texts at once (send everything you want to keep). Validated against the current (or the newly sent) params. Bumps version.
paramsReplaces the whole list. Every {placeholder} in the stored texts must still be declared, otherwise the change is refused. Bumps version.
categoryOne of the three.
activetrue or false.
validFrom, expiresAtISO-8601 instants; null clears the bound. A past expiresAt is accepted here (that is how you retire a template at once). expiresAt must be after validFrom.
code, kind, appIdAlways refused: cannot be changed after creation.

Effects, audit

  • Not audited. Takes effect at once for new sends (templates are read from the database when a request is accepted and again when it is delivered).
  • Reversible: patch the previous values back (there is no history of old wording; keep it in your own ticket).
  • Messages that were already accepted use the new wording when they are delivered; deactivating or expiring a template does not cancel them (the delivery path does not check the template's active flag or window).

Scenario

A partner's "promo" template is sending the wrong discount code. You deactivate it (one PATCH), tell the partner, fix the words, and activate it again. Details: the retire runbook.

What partners can do with templates

A partner can only read its own templates (GET /v1/templates, GET /v1/templates/{id}, signed like any partner call) to learn the ids, params and usableNow, and name one in a send request. Anyone else's template id answers 404 template_not_found.

Not built yet

  • Deleting a template, or a version history of old wording.
  • Audit events for template changes.
  • A "send a test" button that renders a template to a staff member.
  • Different behaviour per category (for instance a stricter limit for PROMOTIONAL).
