Bugs and inconsistencies found while verifying

Found by running every action against a dev stack. None blocks daily work; each has a workaround. Nothing was changed in the code.

#WhatReproWorkaround
1Fixed 2026-10-26: website is limited to 300 characters with a clear message. The validator now matches the column: website max 300 (400 validation_failed, fields.website: "max 300 characters"), entryUrl max 500, supportEmail max 320 (the old pattern allowed longer ones). The same check was added for the staff email on POST /staff.PATCH an app with a 301-character website: 400 with fields.website.None needed.
2Fixed 2026-10-26: template changes are now audited. Creating a template writes template.create and editing, activating, deactivating or expiring one writes template.update (target type template, target id the template id; the entry records the staff id, role, client address and, for edits, which fields changed). If the audit entry cannot be written the change is undone and the call answers 503 audit_unavailable.Create and edit a template, then GET /admin/api/v1/audit?targetType=template (verified live).Use the audit log to see who changed a template.
3Fixed 2026-10-26: the app's Audit tab, ?appId=<appId> and ?target=<appId> now include the events about its keys, reviews, reports and templates. Every audit entry records the app it concerns (appId in the response; a migration filled it in for existing entries where the app could be derived from the target or meta.appId). The entry's own target is unchanged (the key, review or report id).Register and revoke a key, then GET /admin/api/v1/audit?appId=$APP_ID: key.register and key.revoke are listed (and with ?target=$APP_ID too).None needed.
4Fixed 2026-10-26: a path that does not exist now returns {"error": "not_found"}. All three services answer framework errors (bad path UUID, unknown route, wrong method, wrong content type, unreadable body) in the {"error": code} shape.GET /admin/api/v1/apps/$APP_ID/nope returns {"error": "not_found"}. Verified.None needed.
5Fixed 2026-10-26 (breaking rename): the usage view's distinct_users_today is now distinctUsersToday, so every field is lower camel case. Anything that read the old key must be changed (the backoffice Usage tab was).GET /admin/api/v1/notification/usage?appId=...: channel, lifetime, today, distinctUsersToday.Use the new name.
6The backoffice says a key revoke is immediate; in fact the notification service caches keys (and app status, addresses, capabilities, limits) for about 15 seconds.Revoke a key, call with it straight away: it may still be accepted for up to 15 seconds.Wait 15 seconds before checking, and before telling a partner a change has not worked.

Not built yet (everything on this page that does not exist)

  • Apps: delete an app; change a slug; text search and paging in the API list; a history of old values; enforcement of allowedOrigins.
  • Capabilities: enforcement of user.*, location.* and pay.request (needs the in-app bridge and the payment feature); the per-user consent step.
  • Payments: the payment flow; enforcement of the payment settings.
  • Keys: edit a label or expiry; a "last used" time; key types other than RSA.
  • Templates: delete; version history; audit events; a test-send button; different rules per category.
  • Notifications: search by externalId or user; cancel or resend a message; carrier delivery receipts; per-user usage; alerts near a limit.
  • Access: per-app roles; staff API keys or service accounts.
  • Environments: a true sandbox separate from the dev providers; per-address labels.
