Logo

Upload and remove an app's logo: formats, size limits and how the image is processed.

Overview

A mini app needs a logo before it can go LIVE. Staff upload an image; Adera checks it, shrinks it, converts it to PNG and stores it in the media storage. Users get a temporary signed link to it in the catalog.

Why this existsLogos come from partners, so the file is never trusted: the server ignores the file name and the declared type, decodes the image itself, and re-encodes it. That removes hidden metadata, odd file tricks and oversized images, and makes every logo the same format and a sensible size.

The rules

RuleValueWhy
Accepted formatsPNG, JPEG, GIF, BMP. The format is detected from the content, not from the file name or Content-Type. WebP, SVG, PDF and the like are refused.Only formats the server can safely decode.
Maximum upload size2 MiB (2,097,152 bytes) per file. Larger: 413 file_too_large. (Deployment setting LOGO_MAX_BYTES; the request itself may not exceed 4 MB per file and 5 MB in total, also answered with 413 file_too_large.)A logo has no reason to be big.
Maximum dimensionsAt most 12,000 pixels on a side and 40 million pixels in total, otherwise 400 validation_failed (image dimensions are too large).Protects against decompression bombs (a tiny file that decodes to gigabytes).
ProcessingScaled down (never up) so the longer side is at most 512 px (setting LOGO_MAX_PX), aspect ratio kept, transparency kept, re-encoded as PNG. Metadata (EXIF and so on) is dropped. An animated GIF keeps only its first frame.One format and size everywhere in the apps.
Not croppedA wide logo stays wide (a 1200x800 upload becomes 512x341). Ask partners for a square PNG with a transparent background, at least 512x512.The server never changes the picture, only its size.
StorageOne object per upload in the media storage at apps/{appId}/logo/{logoImageId}.png. A new upload gets a new logoImageId and the previous object is deleted.A changed logo is never served from an old cache.
The linklogoUrl is a presigned link, valid 60 minutes by default (STORAGE_PRESIGN_MINUTES); a new one is produced on every read. In the user catalog it is the same kind of link.The bucket is private; links expire.

Endpoints

POST/admin/api/v1/apps/{appId}/logoUpload or replace the logo
Who may call
ADMIN or SUPER_ADMIN
Auth
Staff session Bearer token at assurance level aal2 (Authorization: Bearer $TOKEN)
Rate limit
300 requests per minute per client IP at the gateway (HTTP 429 beyond that)
Backoffice
App > General > Logo (the upload button; a warning "No logo yet (needed to go LIVE)" shows while there is none)
Audit name
app.logo
Reversible
Yes: upload the old image again, or remove the logo

Purpose. Sets (or replaces) the app's logo. When to use it. During onboarding (a LIVE requirement), and whenever the partner rebrands.

Request

multipart/form-data with one part named file (the image). No JSON body. Do not set the Content-Type header yourself when using curl's -F.

curl -sS -X POST "$GATEWAY/admin/api/v1/apps/$APP_ID/logo" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@logo.png;type=image/png"

Response (HTTP 200)

The full app. A 1200x800 PNG (122 KB) was uploaded; the stored logo is 512x341 (101 KB):

HTTP 200 OK

{
  "id": "ff6510a9-de00-4fb2-97a4-ce4ad6e377dd",
  "slug": "doc-tmp-admin",
  "logoImageId": "18a1b264-13fd-45e1-b2ae-af13ef2b85d3",
  "logoUrl": "http://127.0.0.1:9000/adera-media/apps/ff6510a9-de00-4fb2-97a4-ce4ad6e377dd/logo/18a1b264-13fd-45e1-b2ae-af13ef2b85d3.png?X-Amz-Algorithm=...&X-Amz-Signature=...(signed, expires)",

Errors

StatuserrorWhen it happensWhat to do
400validation_failed (fields.file)No file part, an empty file, not a supported image, corrupt image, or dimensions too large.Send a real PNG/JPEG/GIF/BMP in the part named file.
403insufficient_roleVIEWER.Use an ADMIN.
404not_foundNo such app.Check the id.
413file_too_largeOver 2 MiB (or over the request limit).Export a smaller file; 512x512 PNG is normally far below the limit.
A text file:
HTTP 400  {"error": "validation_failed", "fields": {"file": "not a supported image (use PNG, JPEG, GIF or BMP)"}}

A 2.4 MB image:
HTTP 413  {"error": "file_too_large"}

Effects, audit

  • Audit: app.logo with meta {"imageId": ...}. The file contents are not logged.
  • The new logo shows in the catalog right away (each read produces a fresh signed link).
  • Idempotent in effect: uploading the same file twice just creates a new image id and deletes the previous object.
  • If storing the new file fails, the app keeps its previous logo (the change is all or nothing).

Scenario

The partner e-mails a 3 MB JPEG. Convert it to a PNG of at most 2 MiB (or let the server shrink it if it is under the limit), upload it, open the app page to check it, then set the app LIVE.

DELETE/admin/api/v1/apps/{appId}/logoRemove the logo
Who may call
ADMIN or SUPER_ADMIN
Auth
Staff session Bearer token at assurance level aal2 (Authorization: Bearer $TOKEN)
Rate limit
300 requests per minute per client IP at the gateway (HTTP 429 beyond that)
Backoffice
App > General > Remove logo (confirmation: "An app without a logo cannot go LIVE")
Audit name
app.logo.remove (only if a logo existed)
Reversible
Yes: upload a logo again

Purpose. Removes the logo. When to use it. When a logo must disappear at once (wrong picture, trademark complaint). The app shows without a logo afterwards.

curl -sS -X DELETE "$GATEWAY/admin/api/v1/apps/$APP_ID/logo" \
  -H "Authorization: Bearer $TOKEN"

Response (HTTP 200)

The full app with logoImageId and logoUrl set to null:

HTTP 200 OK

{
  "status": "LIVE",
  "logoImageId": null,
  "logoUrl": null
}

Errors

StatuserrorWhen it happensWhat to do
403insufficient_roleVIEWER.Use an ADMIN.
404not_foundNo such app.Check the id.

Effects, audit

  • Deletes the stored image. Audit: app.logo.remove, written only when there actually was a logo; removing a logo that is not there answers 200 and writes nothing (safe to repeat).
  • A LIVE app stays LIVE without its logo (verified): the logo is checked only when the status is set. Users then see the app without a picture. You cannot set it LIVE again until a new logo is uploaded (409 not_ready_for_live).

Not built yet

  • Cropping or a square-fit step: the picture keeps its aspect ratio.
  • WebP and SVG logos.
  • A separate dark-mode logo or a banner image.
