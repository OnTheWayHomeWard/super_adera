App details

The public view of a mini app: every field, what is deliberately hidden, the logo link, ratings and publisher information.

Overview

The "public view" of a mini app is everything a user may know about it: what it is, who runs it, how to reach support, how well it is rated and what it is allowed to do. It is the same JSON object in the catalog list and in GET /api/v1/apps/{idOrSlug}. Anything operational is left out on purpose (list below).

Every field

FieldTypeMeaning and how to use it
idstring (UUID)The app's permanent id. Use it for the preferences endpoints (they take only the UUID) and as a stable key.
slugstringPermanent short name, 2 to 40 chars of a-z 0-9 -. Use in deep links such as adera://apps/demo-ride (your scheme) and in any {idOrSlug} path.
nameobject lang to stringDisplay name, max 100 characters per language. en always present; am, om optional.
descriptionobject lang to stringShort description, max 1000 characters per language. May be {}; may lack en.
logoUrlstring or nullTime-limited download link for the logo image (PNG). Staff cannot put an app LIVE without a logo, but they can remove it afterwards, so code defensively and show a placeholder tile when it is null. See Logo.
brandColorstring or nullAccent colour as #RRGGBB (upper-case hex), for tile backgrounds, headers, buttons on the store page. Optional: staff may leave it unset, so keep a default accent.
categoriesarray of string0 to 10 lower-case words (food, tools...). Free-form, not a fixed list.
marketsarray of stringWhere the app is offered: ET, US. Never empty (defaults to ["ET"]).
publisherobjectWho runs the app: name (display name), legalName (registered company name), supportEmail, supportPhone, website. Every key is always present; each can be null (staff cannot put an app LIVE without a support email, but can clear it later, so do not assume it is there). See Publisher and support.
entryUrlstring or nullThe https address of the mini app's start page. Today: show it as the "Open" target / website link; do not embed or auto-open it expecting a user-data handover (see Entry URL).
ratingAvgnumberAverage of the visible reviews, rounded to 2 decimals (3.3, 5.0). 0.0 when there are none.
ratingCountintegerNumber of visible reviews (hidden ones are not counted).
permissionsarray of objectWhat staff have granted this app. Each: capability (key), description (English only), reason (object lang to string, may be {}). Sorted alphabetically by key. See Capabilities and permissions.

What users never get

Staff see a richer object (the "admin view"). These parts are intentionally absent from the public view, so do not look for them and do not ask backend colleagues to "just add" them without a product reason:

Field staff can seeWhy users do not get it
statusUsers only ever get LIVE apps, so the field would always say LIVE.
priorityInternal ordering knob; the effect is already in the array order.
allowedOriginsWeb origins the mini app may be loaded from or talk to. It is a security setting for the (not yet built) launcher, not something to display.
extraFree-form JSON staff keep on the app (up to 16 KB). Internal.
logoImageIdInternal object id (the same id is visible inside logoUrl's path).
createdAt, updatedAtNot part of the public contract. There is no "last updated" to show.
Capabilities that are DENIED or SUSPENDED, with their reasonsUsers see only what the app can do, never what it was refused.
Payment settings (allowed currencies, hold, min/max amount)Operational limits for the payment feature, which is not built.
Notification limits (per user per day etc.)Operational. Users cannot see how many messages an app may send.
Partner keys, allowed server addresses (environments)Partner-side security material.

Logo: URL, loading and refreshing

  • logoUrl is a pre-signed link straight to the object store (in dev http://127.0.0.1:9000/adera-media/apps/<appId>/logo/<imageId>.png?...). It does not go through the gateway and needs no Authorization header: the signature in the query string is the credential. Do not add your session token to it.
  • It is valid for 60 minutes (X-Amz-Expires=3600; the server setting is STORAGE_PRESIGN_MINUTES, default 60). A new link, with a new signature, is produced on every API call, so two calls give two different strings for the same image.
  • The image is always a PNG, at most 512 by 512 pixels (staff uploads are re-encoded, fitted inside a square, transparency kept). Verified: the demo logos download as image/png, under 1 KB. Treat it as a square icon; do not stretch it. A transparent background is possible, so put it on a tile coloured with brandColor or a neutral surface.
  • Replacing the logo gives it a new image id, so the path changes. That makes the path (without the query) an ideal image-cache key: same path, same pixels. Do not key the cache on the full URL.
  • Refreshing. If an image request fails with 403 (link expired, typically because the list was cached for more than an hour), re-fetch the app (detail is enough) and retry once with the new logoUrl. Do not retry the old URL. With a disk image cache keyed by path you rarely need the URL at all after the first download.
  • If logoUrl is null (staff removed the logo of a LIVE app) or the download fails, draw a placeholder: the app's initial on a tile filled with brandColor.
  • In production the host will be the production object store's public address; always use the URL exactly as given and never rebuild it from parts.

Brand colour

A string like #1E78C8, always six hex digits with a leading #, upper-case. Optional (null when staff did not set one). Use it for the tile background, the header of the store page and the primary button on that page. Keep text readable: compute the contrast and switch the foreground between white and near-black. Do not use it for status colours (errors, ratings) and ignore it if it is too close to your background in dark mode.

Rating average and count

  • ratingAvg is the arithmetic mean of the visible reviews' stars (1 to 5), rounded to two decimals, as a JSON number. ratingCount is how many reviews that is. Verified example: demo-food returns 3.3 and 10.
  • Both are recomputed by the server every time a review is created, edited, deleted or hidden/restored by staff. Hidden reviews are excluded from both.
  • When ratingCount is 0, ratingAvg is 0.0: show "No ratings yet", not "0.0".
  • Show one decimal (3.3) and the count in brackets. The detail does not include the per-star histogram; you can build a rough one only from the reviews list, which is paged and anonymous, so do not.
  • Reviews of a user who was later suspended or deleted still count until staff hide them (see Known issues).

Publisher and support

The publisher object tells users who is behind the mini app. Show the brand-level name under the title ("by Deliver Addis"), and the legalName (registered company) in an "About this service" section when present. supportEmail is required to go LIVE and so is normally present (it can be cleared later): use it for a "Contact support" row (mailto:). supportPhone (up to 30 characters, free text, usually in international format) and website (https URL, up to 500 characters) are optional: hide the row if null. These values are entered by staff and are not verified to be reachable. Seeded apps use support-*@example.com addresses, which do not receive mail.

Entry URL and allowed origins

  • entryUrl is the https address where the mini app starts (or null). Today it is the app's public web address. You may show it as an "Open website" action in the system browser. Launching a mini app inside the super app is not built: there is no web-view bridge, no session handover and no per-user consent step yet. Do not pass the user's token or id to it.
  • allowedOrigins (the origins the mini app may be embedded from and call) exists only in the staff view. It is not returned to users, and nothing in the user API needs it.

Not built yet on this page

  • Screenshots, a long description, version, size, changelog, "what is new".
  • Opening the mini app inside the super app with a handover of the user's identity.
  • A "similar apps" or "more from this publisher" lookup.

Endpoint

GET/api/v1/apps/{idOrSlug}Get one mini app (the store page data)
Who may call
Signed-in end user.
Client path
/api/v1/apps/{idOrSlug} (gateway route apps-catalog, 300 requests per 60 s per client IP).
Headers
Authorization: Bearer $TOKEN
Implemented in
registry-service: AppPublicController#detail, AppService#publicView

Purpose

Returns the public view of a single app. The shape is identical to a catalog list item. Use it when the user opens a store page (to get fresh rating, permissions and a fresh logo link), when you open an app from a deep link or a notification (you only have a slug or id), and to re-check that an app is still LIVE.

Request parameters

NameInTypeRequiredConstraintsWhy it exists
idOrSlugpathstringyesThe app's UUID or its slug. A value that parses as a UUID is looked up as an id; anything else is looked up as a slug.Links use the readable slug; the id is what other APIs (preferences) need.

curl -s "$GATEWAY/api/v1/apps/demo-ride" \
  -H "Authorization: Bearer $TOKEN"

Example: unknown or not-LIVE app

curl -s -i "$GATEWAY/api/v1/apps/demo-paused" -H "Authorization: Bearer $TOKEN"
HTTP/1.1 404 Not Found
Content-Type: application/json

{"error":"not_found"}

Errors

StatusError codeWhen it happensWhat the caller should do
404not_foundNo app with that id or slug, or the app exists but is DRAFT, PAUSED or KILLED. The two cases are deliberately indistinguishable.Remove the app from any cached list and show "not available". Do not retry.
401(empty body)Bad or missing session.Sign in again.
429(HTML page)Gateway rate limit.Back off.

How to use it

  • Render the store page from this response; use the permissions array for the "What this app can access" section.
  • Do not call it for every tile on the home grid; the list already has the same data.
