8f. Operational endpoints

Health, metrics, dev helpers, the public signing key and what the gateway does on its own. These are not part of any client contract, except the JWKS document which partners depend on. 10 endpoint blocks plus gateway behaviour and tool health tables.

Reachability

Actuator, /dev/messages and every /internal/** path are not routed by the gateway. They exist on the service ports 8085-8087, which compose publishes to 127.0.0.1 only so developers can reach them. In production unpublish those ports (SETUP section 12): then they are only reachable inside the compose network, where Prometheus scrapes them.

Audience

120 per 60 s per client IP (gateway route partner-jwks)
Implemented in

Purpose

Publishes the public half of the key Adera uses to sign API responses and callbacks to partners (scheme ADERA-SIG-1, RS256). A partner fetches it once (the answer is cacheable for 1 hour), then verifies the X-Adera-Signature of every response and callback against it (signing). The same document is available directly from notification-service on the dev port.

Purpose

The gateway answers browsers' preflight requests itself. Only the origin http://localhost:3000 is allowed today (the dashboard dev server). Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS; request headers: Authorization, Content-Type, X-Request-Id; X-Request-Id is exposed to scripts; preflight results are cached 3600 s. Mobile apps are not browsers and ignore CORS.

Calling a service port directly

The dev host ports (8085-8087) bypass the gateway. The services therefore check the shared secrets themselves; without them, requests are refused:

Call (direct to the service)Result
GET :8086/api/v1/me with X-User-Id but without X-Gateway-Secret401 {"error":"unauthorized"}
same with the secret but without X-User-Id, or a non-UUID id401 {"error":"unauthorized"}
GET :8085/api/v1/me/notifications without the secret401 {"error":"unauthorized"}
GET :8087/api/v1/apps and /admin/api/v1/apps without the secret401 {"error":"unauthorized"}
