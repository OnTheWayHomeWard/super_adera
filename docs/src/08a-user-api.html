8a. End-user API

What the Flutter app calls with a session token: profile, location, avatar, devices, logout, per-app mute, the notification inbox and the mini-app catalog. 23 endpoints.

Conventions on this page

All paths are relative to the gateway, $GATEWAY = http://127.0.0.1:9080 in dev. $TOKEN is the Kratos session_token returned by sign-up or login (8e); $APP_ID and $ITEM_ID are UUIDs taken from earlier answers. Examples were captured on 2026-10-25 against the dev stack (console SMS, Mailpit) with a throwaway user and a throwaway LIVE mini app, both deleted afterwards; phone numbers and signed-URL secrets are masked.

Error bodies from our services are {"error":"<code>","fields":{...}} (fields only for validation). Three things do not follow that shape: errors produced by the gateway (empty 401, HTML 429, 404 {"error_msg":"404 Route Not Found"}), a few framework default bodies (415, a bad UUID in a path of user-service, noted per endpoint), and Kratos' own errors.

How a request is authenticated

  1. The app sends Authorization: Bearer $TOKEN to the gateway (a Cookie header is forwarded too, for browsers).
  2. APISIX's forward-auth plugin calls user-service GET /internal/auth/verify with those headers plus X-Gateway-Secret. user-service asks Kratos whoami and answers 200 with X-User-Id, or 401.
  3. APISIX copies X-User-Id onto the forwarded request, overwriting any value the client sent, and sets X-Gateway-Secret so the service knows the request came through the gateway.
  4. The service trusts X-User-Id only if the secret matches. Calling a service port directly without the secret gives 401 {"error":"unauthorized"} (8d).

Why: Kratos' whoami returns the identity in its body, not in headers, and services should not each implement session checking. One small translator endpoint keeps every service simple. Spoofing check: a request with a forged X-User-Id still returned the caller's own profile (the gateway overwrote the header; verified by tests/e2e/journey.py).

Purpose

Multipart upload of one image. The server decodes it, centre-crops to a square, resizes to at most 512 px, flattens transparency and re-encodes it as JPEG. That drops EXIF (GPS, camera) data and neutralises odd or hostile files; dimension limits guard against decompression bombs. The file is stored in RustFS at avatars/{userId}/{imageId}.jpg and the previous image is deleted. The response is the full profile with a fresh signed avatarUrl.

Call right after login and whenever the Firebase SDK rotates the token. Idempotent. Rules: an FCM token is unique, so registering a token that already exists moves it to the current user and re-activates it (one phone, two accounts over time). When installationId is given, a rotated token replaces the old token of that installation. The token itself is never echoed back.

One call that fully signs a device out: removes its push token (so the next person on the phone does not get this user's notifications) and revokes the Kratos session behind the bearer token. Kratos has no logout hook for native apps, which is why this lives in our service instead of being automatic. The body is optional; if it names a device, that device is removed first.
