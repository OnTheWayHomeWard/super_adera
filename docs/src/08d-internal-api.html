8d. Internal service-to-service API

The endpoints that exist only so one component can call another: the gateway asking who a session belongs to, Kratos handing over events, notification-service asking the registry and user-service what it needs to deliver. 11 endpoints. None of them may ever be reachable from outside.

Never expose

No gateway route points at any /internal/** path. Verified on 2026-10-25: every /internal/... call made through http://127.0.0.1:9080 answered 404 {"error_msg":"404 Route Not Found"}. The protection is therefore (1) no route, (2) secrets on most endpoints, (3) the compose network. In dev the service ports 8085-8087 are published on 127.0.0.1, which is how the examples below were captured (secrets loaded from .env into shell variables and never printed).

Rules that follow: secrets are compared in constant time; an empty configured secret disables its check (for local dev; registry-service logs a warning at start); user-service does not check any secret on /internal/kratos/after-registration and notification-service checks none on /internal/kratos/* (known limitations: Kratos' static hook config; planned shared-secret header).

Purpose

The translator that turns a Kratos session into headers. APISIX calls it before every protected user request, passing the client's Authorization and Cookie headers. It asks Kratos whoami and answers 200 with X-User-Id (the Kratos identity id) or 401. APISIX then copies X-User-Id onto the real request, replacing anything the client sent. Kratos' own whoami returns the identity in its body, not in headers, so this small endpoint is what lets the gateway hand the user id to any service.

Request parameters

NameInTypeRequiredConstraintsWhy it exists
Authorizationheaderstringone of the twoBearer <session_token>The user's session.
Cookieheaderstringone of the twoKratos session cookieBrowser sessions.
X-Gateway-Secretheaderstringyesmust equal the configured gateway secretProves the caller is the gateway; otherwise any container could probe sessions.

Example: valid session

curl -s -i "http://127.0.0.1:8086/internal/auth/verify" \
  -H "X-Gateway-Secret: $GATEWAY_SECRET" \
  -H "Authorization: Bearer $TOKEN"
HTTP/1.1 200
X-User-Id: <kratos identity id, a UUID>
Content-Length: 0

Verified: the returned id equals the identity id of the session (checked in the capture run). Headers are not stored in the raw capture; the id is shown as a placeholder.

How to use it

  • The response body is empty on success; the gateway only reads the X-User-Id header.
  • Why per-request calls to Kratos and no JWT: sessions can be revoked instantly (logout, 'sign out everywhere'); a self-contained token could not be, and the extra hop is a few milliseconds inside the Docker network.

Purpose

Gives a user their id for one app: u_p_ plus the first 32 hex characters of HMAC-SHA256(ALIAS_HMAC_SECRET, userId:appId). The same user has a different id in each app and the partner cannot map it back to a real user or to the same user in another app, so a partner data leak links to nothing else. The mapping is stored in app_user_alias because resolving needs the table (an HMAC cannot be reversed). Minting twice returns the same alias. It also makes sure the user has a profile row.

X-Internal-Secretheaderstringyesinternal secretOnly services may mint aliases.

Purpose

One call that tells the delivery side everything about an app for this deployment's environment (ADERA_ENV, always used): status, whether it is usable (DEV works for any app that is not KILLED, so partners can integrate before going live; PROD only when the app status is LIVE), the granted capabilities, the per-channel limits and the allowed server addresses (CIDRs) of that environment. Purpose

Every SMS Kratos wants to send (registration and login codes) arrives here, and this service decides how it is delivered: per-recipient limits first, then the live-mode allowlist, then the provider (console in dev, twilio live), then a row in send_log (masked recipient + hash, never the code). Why a courier of our own: it is the single choke point for SMS cost control and for the dev/real switch (SMS_PROVIDER).

Errors

StatusError codeWhen it happens
400(Spring default JSON)to or body blank: bean validation here is not mapped to the Adera error shape.
400invalid_requestBody is not valid JSON (captured on the email endpoint).
502delivery_failedThe real provider failed (body also has code, e.g. the Twilio error). Kratos then keeps the message queued and retries; this is intended.
200(status = suppressed or skipped)Per-recipient limit reached (suppressed, 5 per hour / 10 per day for SMS) or live allowlist mismatch (skipped). Always 200 on purpose: Kratos retries non-2xx answers, which would defeat the limit. The user never gets a code and Kratos does not know.

How to use it

  • The success answer is {"status":"sent","provider":"console"}; provider is twilio in live mode.
  • A real send is a cost: never point this at a live provider without NOTIFY_LIVE_ALLOWLIST (delivery modes).
